# cover-variants 设计 brief

10 套陈厂长 cover 设计探索，用户审核后会从中挑 1-3 套扩展到其他 slide_type（hook/bullets/compare/cta）。

## 硬约束（违反必返工）

### 视觉规格
- viewport **固定** `1080×1920`（竖屏短视频画框），`html, body { width: 1080px; height: 1920px; overflow: hidden; }`
- 背景深色：`#080808` / `#0a0a0a` / `#111` 三选一或渐变深色
- 主调色：金色 `#c9a227` / `#d4af37` / `#e8c46b`；琥珀辅 `rgba(180,100,20,0.5)`；白文字 `#ffffff` / `rgba(255,255,255,0.78)`
- 字体：`'Microsoft YaHei', 'PingFang SC', SimHei, sans-serif`；西文数字可叠 `'Inter', 'SF Pro Display', system-ui`
- 不要用 emoji；不要用图片/SVG 外链；不要用外部字体；不要用 CDN
- **严禁**出现 "weelume" / "WEELUME" / "weelume.com"。品牌只能用中文 "微域生光"

### 动画规格
- 用浏览器原生：CSS animations / keyframes / transitions / Web Animations API / requestAnimationFrame
- **禁用**外部 JS 库（包括 Motion One / GSAP / framer-motion）
- 动画总时长 6.0–7.0 秒：
  - 0–1.5s 入场（fadeUp / 划线 / 数字 count-up 等）
  - 1.5–5.0s 信息层次铺开（stagger / 数据轮播 / 元素切换）
  - 5.0–7.0s **末态定格**（最后 ≥1.5s 静止，便于录屏抓帧）
- 渲染管线是 Patchright 启动 headless Chromium **录屏** mp4，不是单帧截图。所以动画必须真的有时间轴
- 首帧不能白屏：所有动画首帧应是末态的 opacity:0 / transform 起始态，但**背景颜色和基础排版必须立刻可见**

### 文件结构
- 单文件 HTML：内联 `<style>` 和 `<script>`（不要外部资源）
- 顶部添加注释块：

```html
<!--
  cover-vN — <设计名称>
  设计意图：<3-5 句话，说清楚这套的视觉气质 / 信息组织方式 / 动效套路>
  数据维度：<列出本套用了哪 6+ 个数据点>
  动画时间轴：<列出 t=0/1.5/3/5/7 各时间点画面状态>

```

- 文件路径示例：`D:\code\weelume-base\studio-kit\.claude\skills\blogger-breakdown-shortvideo\templates\cover-variants\cover-v01.html`
- 文件能直接 `file:///D:/.../cover-v01.html` 双击在浏览器打开看到完整动画 + 末态

### 同 Agent 两套之间的差异
你被分派两套，**视觉气质必须显著不同**——不允许两套是"换颜色/换字号"的微调。差异点可包括：
- 主视觉骨架（中央对称 vs 边角错位 vs 网格 vs 流体）
- 主要动效（数字 count-up vs 元素 stagger vs 路径绘制 vs 粒子流动）
- 信息呈现密度方式（卡片矩阵 vs 时间脊柱 vs 仪表盘 vs 跑马灯）

### 验收 checklist（每套自查）
- [ ] viewport 严格 1080×1920，无横向滚动

- [ ] 至少 6 个数据维度同时呈现
- [ ] 动画总时长 6.0–7.0s，末态 ≥1.5s 定格
- [ ] 完全无外部资源（CDN / 图片 / 字体 / 库）
- [ ] 不含 "weelume" 任何形式
- [ ] file:// 打开能看到完整动画
