# copywriting.md — 小红书图文文案规则手册

本文件是 Claude 在 Step 2 生成 `script.json`（schema = `XhsDoc`）时必须遵守的文案规则。规则具有约束力，**不允许为了"效果更好"而绕过任何约束**。

读取顺序硬约束：先读 `methodology-primer.md`，再读本文件，最后读 `outline.json`——关键词不熟会写出空话，outline 不熟会写出离地话。

---

## 0. 小红书图文 ≠ 短视频脚本

不要把短视频的 narration 思维带进来。小红书图文的核心差异：

| 维度 | 短视频脚本 | 小红书图文 |
|---|---|---|
| 媒介属性 | 听觉为主，字幕辅助 | **阅读为主，无声** |
| 单元独立性 | 上下张 narration 强连贯 | **每张独立成立**（用户刷到任意一张都要看得懂） |
| 信息密度 | 时间维度铺开，每张 narration 100+ 字 | **空间维度压缩**，单张 ≤60 字解读 + ≤16 字标题 |
| Hook 形态 | 黄金 3 秒口播钩子 | **封面 14 字内主标 + 反共识 / 信息差** |
| 强调手段 | 语气、停顿、口播重音 | **大字号、极光渐变、引号包裹原话** |
| CTA 行为 | "评论区告诉我"等互动钩子 | **"关注"+"看下一篇"等动作钩子** |
| 方法论关键词嵌入 | narration 中口播说出 | **point_title 或 point_kicker 中视觉呈现** |

记住一句话：**短视频是"听完才懂"，小红书是"扫一眼就懂"**。

## 1. 小红书爆款图文的 3 大原则

### 原则 1：单图信息密度 > 系列连贯性

每一张图都必须能**独立成立**——用户在信息流里只刷到第 4 张，也要能直接看懂这条洞见，不需要"先看前面"。

- ❌ point 02 写"前面我们说了 X，那么这一张……"（依赖上张）
- ❌ point 04 写"接下来看第 3 点……"（依赖序号顺序）
- ✅ 每张 point 都用一个独立的钩子开场（title 自己就有锋利度）

实操：写完 8 张之后，**任选一张孤立起来读**，问自己"如果用户只看到这张，ta 能记住什么"。答不上来——这张得重写。

### 原则 2：标题 hook（封面 + 钩子）必须 ≤ 14 字主标题，制造"信息差"或"反共识"

封面 + 钩子两张是流量入口，决定点开率。它们的主标题（`cover_title_line_1` / `hook_big_line_1`）每行硬上限 ≤ 10~14 字（具体见 `visual-spec.md`），必须满足以下 3 类之一：

- **信息差**："这个博主真正赚钱的，不是带货"
- **反共识**："不是粉丝多就能复制"
- **数字反差**："128 万粉丝 · 0 投流"

❌ 不允许的封面标题：
- "今天我们来拆解 XX 博主"（流量入口写成了笔记开场白）
- "XX 博主的运营技巧分享"（无 hook，纯目录式）
- "5 个你必须知道的运营技巧"（标题党且无信息差）

### 原则 3：引用比解读更带情绪——能用原话尽量用原话

`point_quote` 字段（每张 point 可选）是单张图最有"现场感"的一环。原则：

- **能从 `outline.top_quotes` 找到原话，就引原话**，不要自己改写。
- 引用必须用直引号 `"..."` 或竖排引号 `「」` 包裹（模板会按 ink-soft 斜体渲染）。
- `point_quote_source` 必须标注原话出处章节名（如「定位演化」/「变现链路」），≤ 16 字。
- 引用 + 解读组合是最强：**`point_insight` 给出洞见 → `point_quote` 用原话佐证**。

❌ 不允许：编造原话、把博主从未说过的话改写后引用、把博主自传式语录拼接出"伪原话"。

## 2. 每种 card_type 的写作模板（逐字段好例 vs 坏例）

### 2.1 cover（00）封面

| 字段 | 限制 | 好例 | 坏例 |
|---|---|---|---|
| `cover_kicker` | ≤ 14 字 | "上班族减脂赛道" | "我们来分析一个博主"（≥14 字且无信息） |
| `cover_title_line_1` | ≤ 10 字 | "这个博主" | "今天给大家拆解的" |
| `cover_title_line_2` | ≤ 10 字 | "怎么把 128 万粉丝" | "运营做得很好"（无信息差） |
| `cover_title_line_3` | ≤ 14 字（可空） | "做成 2C2B 两条变现" | "今天就来一起看看吧" |
| `blogger_name` | ≤ 16 字 | "张三健身" | "我们最近发现的一位很优秀的博主" |
| `blogger_followers` | ≤ 12 字 | "128 万粉丝" | "拥有约 128 万粉丝量级" |

封面主标题（3 行）的整体节奏建议：**主体 + 动词 + 结果**，把"who / did what / 结果是什么"压成 30 字以内。

### 2.2 hook（01）钩子

| 字段 | 限制 | 好例 | 坏例 |
|---|---|---|---|
| `hook_kicker` | ≤ 14 字 | "一句话答卷" | "我们的拆解结论是这样的" |
| `hook_big_line_1` | ≤ 10 字 | "不是粉丝多" | "粉丝多并不一定" |
| `hook_big_line_2` | ≤ 10 字 | "就能复制" | "代表可以被复制" |
| `hook_big_line_3` | ≤ 10 字（可空） | "是「他做对了什么」可以学" | "我们应该看的是他做对了什么" |
| `hook_sub` | ≤ 24 字 | "下面 5 张图，是他做对的事" | "请大家继续往后看，下面我们将详细说明他做对的 5 件事情" |

hook 的关键是**让用户产生"我得继续看"的强压力**。3 行主文应当构成一个完整的反共识句子：
- A "不是 X" → B "就 Y" → C "是 Z" 三段式
- A "粉丝多 ≠ 能复制" → B "真正能复制的" → C "是「方法」" 推进式

### 2.3 point（02~06）章节亮点

5 张 point 共用同一套模板，结构 = `编号 + kicker + title + insight + 可选 quote`。

| 字段 | 限制 | 好例 | 坏例 |
|---|---|---|---|
| `point_no` | 固定 `01`~`05` | `01` `02` `03` `04` `05` | `02` `03` `04` `05` `06`（误把"亮点序号"写成"页码") |
| `point_kicker` | ≤ 12 字 | "选题策略" / "画等号" | "我们觉得他做得不错的地方" |
| `point_title` | ≤ 16 字（2 行内） | "选了谁，比拍什么更早决定" | "他的内容选题策略和定位人群是非常重要的"（≥16 字） |
| `point_insight` | ≤ 60 字（2~3 行） | "他把'上班族减脂'画上了等号——这一类人，他全占了。不是减脂博主里最专业的，但是最像你身边那个人。" | "经过我们的深度分析，我们认为该博主在定位上做得比较深入。"（书面语 + 无具体洞见） |
| `point_quote` | ≤ 50 字（可空） | `"我不是教练，我只是个比你早开始的人。"` | （编造的话） |
| `point_quote_source` | ≤ 16 字 | "「定位演化」" | "来源于该博主的某次直播" |

**5 张 point 的差异化原则**：5 张必须从 5 个不同维度讲博主做对的事，**不允许 5 张都讲"定位"或"变现"**。建议组合（任选 1 套）：

- **方法论关键词组**：画等号 / 视觉锤 / 选题五方向 / 完播 / 离钱近
- **5W 结构组**：选了谁 / 拍什么 / 怎么说 / 怎么稳 / 怎么变现
- **数据反差组**：粉丝结构 / 完播率 / 互动密度 / 涨粉曲线 / 变现单价

**方法论关键词嵌入**：5 张 point 中**至少 3 张**的 `point_title` 或 `point_kicker` 显式嵌入 1 个 `methodology-primer.md` 关键词（精确字符串匹配）。例如 `point_kicker = "画等号"` 或 `point_title = "完播率撑住了算法"`。

### 2.4 cta（07）行动号召

| 字段 | 限制 | 好例 | 坏例 |
|---|---|---|---|
| `cta_kicker` | ≤ 16 字 | "看 100 个博主拆解" | "如果你觉得这篇笔记对你有帮助" |
| `cta_big_line_1` | ≤ 8 字 | "看他怎么走" | "你想知道他怎么走的吗" |
| `cta_big_line_2` | ≤ 10 字 | "不如先看" | "我建议你不如先看一下" |
| `cta_sub` | ≤ 28 字 | "关注 微域生光，每周拆一个真实跑出来的博主" | "请点击关注我们的账号，我们每周更新拆解内容欢迎您的关注" |
| `cta_brand` | **固定** `"微域生光"` | `"微域生光"` | `"Weelume"` / `"weelume.com"` / `"微域生光 weelume"` |

`cta_brand` 是写入硬约束的字段——`XhsCard.cta_brand` 默认值就是 `"微域生光"`，**不允许改成英文 / 域名 / 双语并列**。

## 4. 三套角度模板（用于 Step 2.2 起 3 份草稿时一一对应）

### A · 方法论拆解角

切入：把博主做法对号入座到 微域生光 Playbook 关键词。

骨架：5 张 point 每张绑定 1 个 Playbook 关键词，`point_kicker` 直接写关键词本身。

| Slide | 推荐字段填法 |
|---|---|
| cover | kicker=「方法论拆解 · 上班族减脂」/ title="这个博主 / 怎么把 X 件做对的事 / 放大成 128 万粉丝" |
| hook | kicker=「Playbook 视角」/ big="不是粉丝多 / 就能复制 / 是「方法对」可以学" / sub="下面 5 张图是他对应 Playbook 的 5 个动作" |
| point 01 | kicker="**画等号**" / title="选了谁，比拍什么更早决定" |
| point 02 | kicker="**视觉锤**" / title="他自己就是视觉锤" |
| point 03 | kicker="**选题五方向**" / title="选题只押人和情两路" |
| point 04 | kicker="**完播**" / title="完播率撑住了算法" |
| point 05 | kicker="**离钱近**" / title="变现只走离钱近一路" |
| cta | kicker=「看 100 个博主拆解」/ big="看他怎么走 / 不如先看 / 他在哪里走过" |

气质：硬核 / 系统化 / 适合泛运营垂类用户

### B · 心路反差角

切入：从"他凭什么不是粉丝多就能复制"的反共识切入，让普通用户产生"原来如此"的共鸣。

骨架：5 张 point 按"选了谁 / 拍什么 / 怎么说 / 怎么稳 / 怎么变现"的故事线展开，每张都用一句反共识金句开题。

| Slide | 推荐字段填法 |
|---|---|
| cover | kicker=「心路拆解」/ title="他粉丝 128 万 / 但你复制不了的 / 是「他先选了谁」" |
| hook | kicker=「先想清楚 5 件事」/ big="不是因为他粉丝多 / 你才学不来 / 是因为他想清楚了 5 件事" |
| point 01 | kicker="选了谁" / title="不是给所有人拍" |
| point 02 | kicker="拍什么" / title="不教知识，只拍人" |
| point 03 | kicker="怎么说" / title="像在和你饭桌上聊" |
| point 04 | kicker="怎么稳" / title="赛马跑同一个公式" |
| point 05 | kicker="怎么变现" / title="变现路径只留一步" |
| cta | kicker=「100 个博主的心路拆解」/ big="他想清楚的 5 件事 / 你也可以 / 一件件想" |

气质：故事感 / 共鸣型 / 适合泛创作者用户

### C · 数据骨架角

切入：从 followers / 关键章节数据切入，"用数据看他怎么做对了"。

骨架：5 张 point 每张以一个关键数字开场，`point_no` 之外，正文里再嵌一个具体数字（如"128 万粉丝里 80% 上班族"）。

| Slide | 推荐字段填法 |
|---|---|
| cover | kicker=「数据骨架拆解」/ title="128 万粉丝 / 0 投流 / 看完你会发现这不是偶然" |
| hook | kicker=「5 个数字读懂他」/ big="不是看他粉丝多 / 是看 5 个数字 / 决定了他能跑通" |
| point 01 | kicker="粉丝结构" / title="128 万里 80% 是上班族" |
| point 02 | kicker="完播率" / title="前 3 秒留住 70% 的人" |
| point 03 | kicker="互动密度" / title="每 100 个赞，3 条评论" |
| point 04 | kicker="涨粉曲线" / title="月涨粉 5 万，连续 12 个月" |
| point 05 | kicker="变现单价" / title="一个 2C 课程，客单 ≥ 千元" |
| cta | kicker=「100 个博主的数据骨架」/ big="数字不会骗人 / 你也可以 / 用数字看你自己" |

气质：理性 / 高密度 / 适合精算型 / B 端用户

**起 3 份草稿时**：A 用方法论 / B 用心路 / C 用数据，**三份角度气质不能重合**。如果博主信息不支撑某个角度（例如 outline 没有具体数据，C 就难写），仍要勉力出，并在草稿摘要里诚实告诉用户"C 因数据不足较弱，建议 A 或 B"。

## 5. 反例清单（违反任何一条必须重写）

### 5.1 禁止口播体

小红书是阅读体，不是听觉体。以下表达是从短视频脚本里"误带"过来的口播体，**禁止**出现在任何字段：

- ❌ "接下来我们看……" / "下面我们来分析……"
- ❌ "首先 / 其次 / 最后"（用作图文上下张连接词时禁止——每张独立）
- ❌ "刚才说到 X，那么……"
- ❌ "好，我们来到第 3 点"

### 5.2 禁止疑问体（封面 hook 之外）

封面 / 钩子允许 1 处反共识疑问，**其他 6 张禁止疑问句**。

- ❌ point_title = "你知道他为什么能跑出来吗？"
- ❌ point_insight = "他是怎么做到的呢？我们来分析一下"

### 5.3 禁止英文品牌 / 域名

可见层只能"微域生光"四字。以下字符串在任何字段中**禁止**：

- ❌ `weelume` / `Weelume` / `WEELUME`
- ❌ `weelume.com` / `www.weelume.com`
- ❌ 任何 `.com` / `.cn` / `.io` 域名
- ❌ 任何 `http://` / `https://` 前缀
- ❌ 中英并列如 `"微域生光 Weelume"` / `"Weelume · 微域生光"`

`cta_brand` 字段的硬默认值就是 `"微域生光"`，不允许修改成任何其他形态。

### 5.4 禁止短板叙事（与短视频版同步）

任何字段都**禁止**出现以下词（指向博主自身问题时）：

- 短板 / 不足 / 欠缺 / 缺点 / 缺陷 / 弱项
- 做得不好 / 还需要改进 / 待提升 / 有待加强 / 不够
- 建议他 / 应该 / 可以更好 / 优化空间 / 改进方向

例外：可以说"行业里大多数博主**做不到** X"等不指向当前博主短板的表达。

### 5.5 禁止"安全话"和"AI 感"

- ❌ "该博主在内容创作方面表现优秀"（AI 体 + 空话）
- ❌ "通过对其作品的深度分析，我们发现"（深度运营 / 我们发现）
- ❌ "受众群体" / "内容矩阵" / "变现路径" / "深度运营" / "私域" / "闭环" / "赋能"

替换：用人话说——
- 受众 → 看他视频的人
- 变现路径 → 怎么赚钱
- 深度运营 → 用心做内容
- 私域 → 粉丝群 / 私人渠道

## 6. 校验清单（写完 script.json 后自查）

在把 `script.json` 交给 `render-xhs` 之前，按以下清单逐条自查。**任一项不过必须重写。**

### 结构
- [ ] `cards.length == 8`（CLI 侧会强校验，但本地先自查可以避免一次失败重跑）
- [ ] `cards[i].index == i` 对所有 i 成立
- [ ] 类型顺序 = `[cover, hook, point, point, point, point, point, cta]`
- [ ] `page_label` 格式 `"NN / 08"`，cover 可为空
- [ ] `point_no` 是 `01`~`05` 而不是 `03`~`07`

### 字数
- [ ] 每个字段都不超过 Section 3 表格中的字数上限（逐字段 `len()` 自查）
- [ ] `cta_brand == "微域生光"`，无英文 / 域名

### 方法论强绑定
- [ ] 5 张 point 中至少 3 张的 `point_title` 或 `point_kicker` 精确匹配至少 1 个 `methodology-primer.md` 关键词
- [ ] 关键词以中文原貌出现（不是英文翻译、不是近义改写）

### 内容铁律
- [ ] 未出现任何短板 / 建议类禁词（Section 5.4 清单）
- [ ] 未出现 `weelume` / `weelume.com` / 任何域名 / 任何英文品牌（Section 5.3 清单）
- [ ] 未出现口播体（"接下来"/"首先 / 其次 / 最后"等，Section 5.1 清单）
- [ ] 除封面 hook 外，其他 6 张未出现疑问句
- [ ] 每张图独立成立——任选一张孤立读，能读懂洞见

### Quote 字段
- [ ] 若 `point_quote` 非空，则 `point_quote` 来源于 `outline.top_quotes` 或 chapters 中的原话，未被改义
- [ ] `point_quote_source` 标注了具体章节名

通过校验后，再调用 `studio-kit render-xhs`。
