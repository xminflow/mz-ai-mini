# methodology-primer.md — 微域生光 Playbook 方法论术语库（小红书图文版）

本文件是 Claude 在 Step 2 写 `script.json`（`XhsDoc` schema）之前必须读取的方法论参考。

小红书图文拆解的本质，是**把博主做对的某一件事，映射到 微域生光 Playbook 9 篇中的某一条方法论上**，让读者扫一眼一张 point 卡，就能识别出"这个动作命中了哪条方法论"，而不只是"这个博主做了什么"。

## 强绑定铁律（违反必须重写）

1. 每份 `script.json` 的 5 张 `point` 中，**至少 3 张**的 `point_title` 或 `point_kicker` 必须**显式嵌入**至少 1 个 Playbook 关键词（精确字符串匹配）。
2. 关键词必须以**视觉可见**方式出现（在 `point_title` / `point_kicker` / `point_insight` 任一字段中以原貌出现），不允许只在心里想了一遍。
3. 一篇图文建议主线支柱 1-2 个，**不贪多**——8 张图塞不下 3 个支柱的展开。建议 5 张 point 围绕 1 个主线支柱的 5 个子动作，或 1 个主线 + 1 个副线各 2-3 张。
4. 严禁分析博主短板（信息不足以支撑判断）。映射只做"做对的事 → 命中哪条方法论 → 现在怎么放大"。

## 1. 九篇核心术语清单（关键词以加粗标出，是 point 字段校验的精确匹配项）

### Foundations · 底层逻辑

判断这个博主能跑出来，是否踩中"内容稀缺 × 效率红利 × 信任纽带"。

可识别关键词：
- **收入=流量×变现** / **流量×变现**
- **流量经济** / **粉丝经济** / **品牌经济**
- **信任前置**
- **效率是风口本质** / **效率红利**

### Positioning · 定位

判断这个博主是否把"一类需求"画上了等号、是否有清晰的视觉锤与文字钉。

可识别关键词：
- **画等号**
- **内容定位三原则**（多维 · 原生 · 高频）
- **痛点+方案** / **痛点方案**
- **视觉锤** / **文字钉**
- **商业定位四阶梯**

### Topics · 选题

判断这个博主选题是否成体系、是否踩中爆款元素、是否做了系列化。

可识别关键词：
- **选题五方向**（人/事/物/趣/情）
- **八大爆款元素**
- **情绪波点**
- **选题系列化**（定量 + 变量）
- **跨领域借鉴**

### Scripts · 文案与脚本

判断这个博主用的是哪一类脚本骨架。

可识别关键词：
- **四型脚本**（聊观点 / 教知识 / 讲故事 / 晒过程）
- **聊观点脚本** / **教知识脚本** / **讲故事脚本** / **晒过程脚本**

### Craft · 拍摄与剪辑

判断这个博主的呈现是否做到表现力优先。

可识别关键词：
- **三分拍七分剪**
- **表现力优先**

### Growth · 增长与投放

判断这个博主是否吃到了算法的标签机制 / 完播率 / 赛马 / 铁粉。

可识别关键词：
- **三层标签** / **三层标签机制**
- **完播** / **完播率**
- **赛马机制**
- **铁粉机制**
- **目的垂直** / **手段多维**

### Monetization · 变现

判断这个博主的变现是否离钱近、路径短，是 2C 还是 2B。

可识别关键词：
- **变现四原则**
- **离钱近** / **路径短**
- **2C2B**
- **4P**
- **客户分层** / **价值排序** / **变现链路**

### Industry · 番外行业卷

如果博主主线属于 5 大行业之一，可以引用对应打法做注脚。

可识别关键词：
- **本地实体** / **专业人士** / **教育培训** / **零售** / **数字产品**

## 2. 博主动作 → 支柱映射规则

判断流程（按顺序逐条试，命中一条即停，最多挑 2 个支柱）：

| 博主的核心成长动作偏向 | 主线支柱（先选 1 个） | 可补充的副线支柱 |
|---|---|---|
| 收窄品类 / 锁人群 / 固定人设 | `positioning`（画等号 + 内容定位三原则） | `foundations`（粉丝经济 / 信任前置） |
| 选题成体系 / 持续踩爆款元素 | `topics`（选题五方向 / 八大爆款元素） | `scripts`（四型脚本） |
| 用某一种脚本骨架反复打 | `scripts`（四型脚本） | `topics` |
| 完播 / 停留 / 互动数据稳定高 | `growth`（三层标签 / 完播 / 赛马机制） | `topics` |
| 持续涨粉、铁粉密度高 | `growth`（铁粉机制 / 目的垂直） | `positioning` |
| 把流量切到 2C 课程 / 训练营 / 知识付费 | `monetization`（2C2B / 变现四原则） | `positioning` |
| 把流量切到 2B 品牌合作 / 探店 / 接单 | `monetization`（4P / 客户分层） | `industry` |
| 处于 5 大行业之一且打法有共性 | `industry`（对应行业） | `monetization` |
| 跨平台 / 跨账号矩阵化运营 | `foundations`（效率红利） | `growth`（目的垂直·手段多维） |

注意：上表只是引导，**不允许只为"凑支柱"硬贴标签**。如果某博主的动作映射不上任何一条，说明信息不足，应该改写 point 内容用更具体的事实描述，而不是硬塞关键词。

## 3. 关键词嵌入句式范例（如何把术语融进 ≤16 字 point_title 或 ≤12 字 point_kicker）

不要硬贴标签，要把术语**自然嵌入字段**。

### 3.1 嵌入 `point_kicker`（≤12 字，直接当章节标签用）

最简单的做法：`point_kicker` 直接等于一个 Playbook 关键词。

| 关键词 | 作为 kicker 的样子 |
|---|---|
| 画等号 | `"画等号"` |
| 视觉锤 | `"视觉锤"` |
| 选题五方向 | `"选题五方向"` |
| 完播率 | `"完播率"` |
| 离钱近 | `"离钱近"` |
| 2C2B | `"2C2B"` |
| 信任前置 | `"信任前置"` |
| 铁粉机制 | `"铁粉机制"` |
| 四型脚本 | `"四型脚本"` |
| 三层标签 | `"三层标签"` |

### 3.2 嵌入 `point_title`（≤16 字，把术语自然嵌入金句）

| 关键词 | point_title 句式 |
|---|---|
| 画等号 | "选了谁，比拍什么更早画等号" |
| 视觉锤 | "他自己就是视觉锤" |
| 选题五方向 | "选题只押人和情两路" |
| 八大爆款元素 | "每条都踩了反差感这一爆款元素" |
| 完播率 | "完播率撑住了算法" |
| 赛马机制 | "赛马机制跑同一个公式" |
| 离钱近 | "变现只走离钱近一路" |
| 2C2B | "同一波粉丝切成 2C2B 两条" |
| 铁粉机制 | "铁粉机制跑出来了" |
| 三层标签 | "他的标签焊死在一格" |
| 信任前置 | "他在变现之前先把信任前置" |

### 3.3 嵌入 `point_insight`（≤60 字，2~3 行解读）

`point_insight` 中可以**用关键词解释博主动作**，让读者获得"原来这叫 X"的恍然大悟感。

例：
- `point_kicker = "画等号"` / `point_title = "选了谁，比拍什么更早决定"` / `point_insight = "他把上班族减脂这件事，画上了等号——这一类人他全占了。不是减脂博主里最专业的，但是最像你身边的那个人。"`

## 4. 一份 xhs 图文的方法论组装范式（5 张 point 的支柱分配）

围绕 1-2 个主线支柱组装 5 张 point：

```
00 cover    博主名 + 一句话定位（不直接说方法论关键词，留到 point 视觉揭示）
01 hook     反共识钩子（不是粉丝多就能复制，是「他做对了什么」可以学）
02 point    亮点 01：主线支柱 · 关键词 A（kicker 直接写关键词）
03 point    亮点 02：主线支柱 · 关键词 B
04 point    亮点 03：主线支柱 / 副线支柱 · 关键词 C
05 point    亮点 04：副线支柱 · 关键词 D
06 point    亮点 05：副线支柱 / 收束 · 关键词 E（也可不带关键词）
07 cta      关注 + 看下一篇（不放方法论关键词）
```

5 张 point 中，**至少 3 张**显式嵌入关键词。建议分布：02 / 03 / 04 必有，05 / 06 可选。

## 6. 主线支柱决策检查

写 `script.json` 之前必须在心里回答以下 4 个问题，任一回答不上来要再读一遍 outline.chapters：

1. 这个博主**做对的核心一件事**是什么？（一句话，≤25 字）
2. 这件事**对应 Playbook 哪 1-2 个支柱**？（指定 1-2 个）
3. 5 张 point 我会**在哪几张** 的 `point_kicker` 或 `point_title` 里**精确嵌入哪几个关键词**？（至少 3 张）
4. 他近期是**怎么把这件事放大**的？（用于最后一两张 point 的 insight；如果想不出，就让收束 point 不带关键词，描述具体事实）

回答完这 4 个问题，再开始 Write `script.json`。

## 7. 在小红书图文中如何使用（与短视频版的差异）

短视频版的关键词嵌入位置是 `narration`（口播听到），小红书图文版的关键词嵌入位置是**视觉文本**（眼睛看到）。两者的承载位置完全不同：

| 维度 | 短视频版（blogger-breakdown-shortvideo） | 小红书图文版（本 skill） |
|---|---|---|
| 关键词出现的字段 | `slides[*].narration`（口播） | `cards[point].point_kicker` 或 `point_title`（视觉） |
| 出现方式 | 口播说出（耳朵听到） | 视觉呈现（眼睛扫到） |
| 嵌入张数要求 | 至少 1 张 narration 出现 | **至少 3 张 point** 出现 |
| 单张承载 | narration 可以连续讲多个关键词 | **每张 point 主打 1 个关键词**（认知留白） |

**在小红书图文中如何使用**：

1. **建议在 `point_kicker` 中直接嵌入关键词**——这是最高效的做法。`point_kicker` 字段就在 point 标题正上方，类似"标签"的视觉位置，读者扫一眼就能识别。
2. **每张 point 至少绑定 1 个 Playbook 关键词**——即使 `point_kicker` 不直接写关键词，也要在 `point_title` 或 `point_insight` 中以原貌出现。
3. **不允许只在 `cover_kicker` 或 `cta_kicker` 中出现关键词**——这两张是"流量入口"和"动作收束"，关键词放这两张相当于没放（读者不会停留细读 kicker，他们会被 hook 拉走或被 CTA 拉走）。关键词必须出现在 5 张 point 的字段中。
4. **认知留白：一张 point 只主打 1 个关键词**——不要在一张 point 的 kicker / title / insight 里同时塞 3 个关键词，会让读者注意力分散。小红书图文是"扫读"媒介，单张图的注意力承载 < 2 个关键概念。
5. **可以重复同一关键词**——5 张 point 中可以有 2 张都打 `画等号`（一张讲"画等号给谁"，一张讲"画等号怎么巩固"），不算违规，反而能强化方法论印象。但 5 张全部用同一个关键词就过度了。
