# 整站模板复刻规范（简版）

适用于当前项目的模板复刻与后续模板制作，以本次微域生光模板的要求为基准。

## 1. 复刻范围

- 覆盖参考站的全部页面、内容结构和主要交互，包括导航、页脚、博客、文章、联系页及政策页面，避免只完成首页。
- 接入现有 `website/src/features/site-templates/` 模板体系，复用注册表、路由和预览能力。
- 图片、字体等素材本地托管，保留来源与许可证记录；新增依赖需先确认。

### 独立源码工程与主站接入

- 新模板的业务源码必须建立在 `D:/code/code-tpl/<id>-template/`，每套模板是独立 Git 工程；遵守 `code-tpl/AGENTS.md` 和 `tpl-format/docs/FORMAT.md`，完整提供 `.tpl` 元数据、规则、修改指南、素材来源及自身验收资料。
- 参考 Deformo 的共享包模式，通用页面、双语内容、主题、组件和运行素材以独立工程为主维护位置。主站 `website/src/features/site-templates/catalog/<id>/` 只保留注册与宿主适配，不复制整套页面源码。
- 本地开发通过 `<id>.local` 引用独立源码并同步该模板素材；生产使用 `vendor` 中固定版本、SHA256 校验的包，配套交付模板锁、依赖声明和包管理器生成的依赖锁。生产不得读取本机 `code-tpl` 路径。
- 独立模板使用自身品牌，不保存主站品牌、联系方式、绝对路径或接入记录；第 4 节的微域生光品牌、模板市场入口及示例备案由主站适配注入。主站接入与联调资料留在本工程。
- 展示截图在独立工程 `.tpl/assets/` 保存，同步映射到主站 `public/templates/<id>/screenshots/`。只管理当前模板，不覆盖其他模板及用户已有修改。
- 未配置 Git 远端地址时，可直接在 [weelume GitHub 组织](https://github.com/orgs/weelume/repositories) 下为当前独立模板工程创建公开仓库，默认名称为 `<id>-template`，无需再次确认创建动作。创建前检查同名仓库，避免重复创建或误用其他工程的仓库；创建成功后，将返回的真实仓库地址同步填写到独立工程 `.tpl/template.json` 的 `gitUrl` 及主站模板的 `gitUrl`。创建失败或权限不足时明确记录原因，不虚构仓库地址。
- 上述授权覆盖公开仓库创建及地址回填；提交、推送、部署或公开上架仍按用户的相应授权执行。分别验证独立工程与主站页面，交付时如实说明未完成项。

## 2. 字体与字号

参考 yiliart 的中文排版，中文化后重新调整比例、行高和留白。

| 用途 | 约定 |
| --- | --- |
| 中文字体 | MiSans，使用真实 400 / 700 字重 |
| 英文与数字 | Poppins，使用 400 / 600 / 700 字重 |
| 首屏大标题 | 手机 28px → 桌面 44px |
| 章节标题 | 24–36px |
| 文章标题 | 26–36px |
| 正文 | 16–17px，行高约 1.8 |
| 导航品牌 | 文字 18px，图形 Logo 24px |
| 导航下载按钮 | 13px，按钮高度 36px；收起时导航整体高度约 54px |

- 字号通过主题令牌和 `clamp()` 管理，避免逐组件随意设置。
- 中文展示标题按语义分行，每行末尾去掉逗号、句号等标点。例如“让每一笔支出 / 更有章法”。
- 标题保持紧凑，卡片高度随内容撑开，检查中文换行及英文长文案的完整显示。

## 3. PC、iPad、H5 三端适配

| 设备 | 标准检查与截图视口 |
| --- | --- |
| PC | 1440 × 1000 |
| iPad | 834 × 1180 |
| H5 | 390 × 844，补测 320px 窄屏 |

- 三端都需实际调整布局，包含导航、卡片、图片、价格、FAQ、表单和页脚；平板采用合适的双列布局，手机以单列和触控操作为主。
- 检查横向溢出、文字裁切、按钮重叠、安全区，以及手机首屏主要操作是否可见。
- 同一响应式官网共用一套页面与业务站点注册，不为设备重复制作站点。
- 本次范围为 PC、iPad、H5，小程序暂不制作。

### 滚动条与滚动体验

- **滚动条属于模板视觉的一部分，必须与网站风格保持一致。** 覆盖整页、弹窗／抽屉、侧栏、长列表、代码块及横向内容区；根据各区域的明暗背景适配轨道、滑块、圆角和悬停状态，避免浅色页面出现突兀的深色粗滚动条，或深色面板沿用刺眼的浅色轨道。
- 滚动条颜色、宽度和圆角通过模板主题令牌集中管理，优先沿用网站的中性色与低饱和强调色。轨道可透明或接近容器背景，滑块应清晰可辨，悬停／拖动时适度增强对比；随网站明暗主题同步切换，不逐页面硬编码。
- 优先使用浏览器原生滚动与 CSS 定制，兼顾 `scrollbar-width`、`scrollbar-color` 及支持的 `::-webkit-scrollbar` 系列伪元素。桌面整页宽度建议 8–10px，容器内建议 6–8px，以实际可拖动性与视觉效果为准；系统覆盖式滚动条、浏览器差异及高对比模式保留原生行为，不强求逐像素一致。不为滚动条单独新增依赖或替换整站滚动引擎。
- 样式仅作用于当前模板及其滚动容器，不污染主站、模板市场或其他模板。整页滚动条若需作用于 `html` / `body`，必须限定模板路由的生效范围，离开时恢复；独立工程维护通用主题，宿主仅负责必要的路由适配。
- 页面只保留一个主要纵向滚动区域，避免 `html`、`body`、页面外壳和预览框同时产生重复滚动条。弹窗／抽屉打开时正确锁定背景，内部内容可滚动，关闭后恢复原滚动位置；内部滚动到边界时避免意外带动背景页面。
- H5 / iPad 优先保留系统触控惯性与覆盖式滚动条，不强制常驻粗轨道、不占用触控空间。桌面端保证鼠标滚轮、触控板与滑块拖动可用；可聚焦的内部滚动区域支持相应键盘操作，并显示清晰的焦点状态。
- 不得为美观统一隐藏滚动条、裁切溢出内容或阻止用户滚动。参考站确实隐藏横向图库／轮播滚动条时，可保留其设计，但必须保留可发现的切换方式、触控及键盘操作；普通页面不应产生意外横向滚动条。
- 优化以减少布局跳动、遮挡和操作阻力为目标。需要时使用 `scrollbar-gutter` 等原生能力稳定布局，并验证不会在移动端或设备预览中留下多余空白；平滑滚动、吸附、视差与滚动触发动效按原站实际行为实现，不额外引入滚动劫持，并尊重减少动态效果设置。

## 4. 中英文与品牌

- 所有页面均提供中英文，覆盖导航、正文、博客、FAQ、政策、表单提示、无障碍标签及界面示意素材。
- 默认中文；英文使用端路径后的 `/en`，切换时停留在对应页面，并保留查询参数和锚点。
- 站内导航使用 Next.js 客户端路由，避免切页时整页刷新或闪白。
- 品牌统一为“微域生光 / Weelume”，导航、页脚及浮动入口使用项目现有 Logo，按背景选择浅底或深底版本。
- 右下角固定放置“微域生光”品牌按钮，参照 Conicorn / Viral 模板：深色背景、浅色 Logo、圆角矩形、细边框及柔和阴影；桌面端显示 24px Logo 与“微域生光 / Weelume”文字，按钮高度至少 44px。不要做成返回当前模板首页的纯 Logo 圆形按钮，也不添加“新模板”推广窗口或装饰箭头。
- 品牌按钮统一使用 Next Link 跳转模板市场 `/templates`，中英文无障碍名称明确为“打开微域生光模板市场 / Open Weelume template marketplace”。手机端可收起文字，保留至少 22px Logo 与 42px 触控高度；桌面距右、下边缘约 24px，手机约 14px，并兼顾安全区及表单、相册控件的操作空间。
- 页脚标语根据当前模板的业务定位编写，避免照搬其他模板文案：“让财务管理更从容”仅用于 Lunera 财务模板，Grovia 团队增长模板使用“让团队成长更有方向”。市场入口为“微域生光：模板市场”；模板备案信息统一复用 `shared/TemplateFiling`，固定显示“示例ICP备00000000号”，仅作演示占位，不使用官网真实备案号或备案查询链接。官网主站保留真实备案组件。

## 5. 卡片、动效与交互

- 卡片统一使用玻璃质感：半透明渐变、背景模糊、高光边框和柔和阴影，由模板主题集中管理。
- 保证文字对比度和层次，避免玻璃叠层影响阅读；移动端调整卡片间距与 sticky 行为。
- **必须完整复刻原站动效**，覆盖所有参考页面及其 PC / iPad / H5 表现，包括首屏与文字入场、错峰动画、滚动触发与视差、悬浮与按压、拖拽与回弹、轮播与循环滚动、菜单、FAQ、页面切换及动态视频等原站实际存在的效果。不得只复刻静态布局，不得遗漏、擅自简化或用统一淡入替代原有效果；用户明确要求删除或调整的效果按用户要求执行。
- 动效优先使用项目现有 `framer-motion` 实现，还原原站的触发条件、运动轨迹、节奏、缓动、循环与停止行为，并保留各端差异；尊重系统减少动态效果设置。
- 复刻前逐区记录原站动效清单，包括触发时机、方向、错峰顺序、时长、循环速度、拖拽回弹和移动端差异；动态视频不得擅自用静态图片替代。验收须实际触发并比较不同时刻的状态，不能用统一淡入、静态截图或路由可访问代替动效还原。
- 禁止自行增加箭头图标、箭头字符或箭头动效，尤其是指向右上角的装饰箭头 `↗`。按钮、文字链接、导航、页脚、作品卡片、图片浮层和图库标题均不得为了装饰或强调可点击性而额外添加箭头；字符、SVG、图标组件和 CSS 伪元素等实现方式一视同仁。只有用户明确要求时才可新增装饰箭头。
- 原站已有或需求明确要求的下滑、返回、翻页、轮播及图库上一张/下一张等功能性方向控件，按需求保留；移除装饰箭头时保留按钮和链接原有功能，不得顺带删除导航、切换或键盘操作能力。
- “下载应用”保持展示按钮，点击无外站跳转；演示表单明确仅做本地校验，尚未发送或保存。

## 6. 预览、截图与验收

- 在线预览在全新标签页打开，支持整站导航和操作；PC 直接打开整站，iPad / H5 使用模拟设备边框。
- 模拟设备内保持真实 CSS 视口尺寸，只缩放外层设备框，保留滚动、菜单、语言切换与表单操作。
- 模板详情页分别展示三端真实截图，至少覆盖首页、功能、博客和联系页，每端四张；记录设备与截图宽高，设计修改后同步更新。
- 完成前通过 TypeScript 检查与改动文件 ESLint，实际运行三端页面，验证中英文切换、站内导航、菜单、FAQ、表单和新标签页预览。
- 动效验收必须逐项对照原站动效清单，在三端实际触发并记录初始、运行和结束状态；循环效果检查持续运行及暂停／恢复，拖拽检查释放回弹，视频检查实际播放。未复刻、存在差异或未验证的项目必须明确列出，不得标记为“完整复刻完成”。
- 滚动条验收覆盖长页面、深浅色区块、弹窗／抽屉、内部列表及横向内容区，检查主题一致性、悬停／拖动反馈、触控与键盘操作、背景锁定与恢复，以及切换模板后样式是否正确清理。PC / iPad / H5 均须实际滚动验证，不能仅凭 CSS 声明或静态截图判定通过；如存在系统原生显示差异，明确记录。
- 检查滚动条出现／消失时导航、内容与固定按钮是否跳动或被遮挡。记录视口尺寸、扣除滚动条后的内容宽度及截图实际像素，区分正常滚动条占宽与真实横向溢出；截图元数据按实际解码尺寸填写，不放大或假定其等于配置视口。
- 检查浏览器控制台、图片加载与横向溢出；交付时说明验证结果及尚未验证的事项。
