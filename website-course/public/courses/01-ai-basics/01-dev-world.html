AI 基础工具学习 · 第一节

开发世界速览

用大白话讲清前端、后端、数据库、终端这四个词， 给后面所有内容打地基。先鸟瞰全貌，再逐个深入。

欢迎进入开发世界。你可能听过"前端""后端""数据库""终端"这些词， 它们听起来像四个互不相干的黑话，其实只是一套系统里分工不同的四个角色。 这一节我们不写一行代码，只把这四个角色的位置、职责、彼此怎么连讲明白。 理解了它们的关系，后面学任何工具、看任何教程，你心里都有一张地图，不会再被术语绕晕。

先给你一个能贯穿全节的比喻：把一个 App 或网站想象成一家餐厅。

前端是店面和菜单——顾客看得见、摸得着、点单的地方； 后端是后厨——顾客看不见，但所有的活儿在这里干； 数据库是仓库和冰箱——食材、订单、会员信息都存在这儿； 终端则是厨房里那台操作台兼对讲机——开发者（厨师长）用它直接下达指令、查看状态。

记住这家餐厅，下面四个概念你就都能对号入座了。

前端

一句话：前端就是你眼睛能看到、手能点的那一层。 网页里的按钮、文字、图片、表单、那个会动的菜单——全是前端。

  • 负责什么：把界面画出来，接收你的点击和输入，再把结果好看地展示给你。
  • 生活类比：餐厅的店面和菜单。装修、座位、菜单的样子，决定你看到什么、怎么点单。
  • 怎么连：它直接面对用户；当需要数据（比如"我的订单"）时，它向后端发请求，拿到结果后负责展示。前端自己不存数据。

后端

一句话：后端是你看不见、却在背后干活的那一层。 判断密码对不对、计算价格、决定能不能下单，这些逻辑都在后端。

  • 负责什么：处理业务规则、做运算和判断、跟数据库打交道，然后把结果交给前端。
  • 生活类比：餐厅的后厨。你只管点菜，炒菜、配料、出餐的流程顾客看不到，但活儿都在这里。
  • 怎么连：前端通过 API（一种约定好的"对接窗口"，让两边能互相喊话）找后端要东西； 后端需要数据时去问数据库，处理完再原路返回给前端。

数据库

一句话：数据库是专门用来长期存放数据的地方。 用户信息、订单记录、商品列表，关机也不会丢，随时能查、能改。

  • 负责什么：把数据整整齐齐地存起来，并能高效地查找、新增、修改、删除。
  • 生活类比：餐厅的仓库和冰箱。食材、库存、会员名单都码放在这里，要用时按需取。
  • 怎么连：它只跟后端对话，不直接面对用户。 后端用 SQL（一种"跟数据库说话的标准语言"，专门用来查和改数据）去取数据，再把它交给前端展示。

终端

一句话：终端是开发者敲命令、直接指挥电脑干活的地方。 它没有花哨界面，就是一个黑框，你打一行字、回车，电脑就执行一条指令。

  • 负责什么：用文字命令来安装工具、启动服务、查看日志、操作文件——不用点鼠标，效率更高、更精确。
  • 生活类比：厨房里的操作台兼对讲机。厨师长不靠菜单点单，而是直接下指令、随时看后厨状态。
  • 怎么连：它是开发者的入口，不属于用户那条链路。前端、后端、数据库都可以从终端被启动、被检查、被操控。

它们如何协作

把四个角色串起来，一次完整的请求是这样跑的：

你点下"提交订单"按钮 →前端收到点击，向后端发请求 →后端处理逻辑、校验并向数据库要数据 →数据库存好/查到记录后返回 →后端把结果回传 →前端把"下单成功"展示给你。

而终端始终在一旁：开发者用它启动这套系统、查看运行状态、排查问题。 这四个角色，就是整个开发世界的地基—— 后面我们学的每一个工具、写的每一行代码，都会落在这张地图的某个位置上。

你常听到的那些词

这些词你多半在新闻、朋友聊天、产品公告里听过，但未必说得清。 这里用大白话、带例子给你对一遍——不用背，混个脸熟，以后再听到不发懵就行。

常听到的"东西"

代码 / 写代码
写给电脑的一条条"指令"，像菜谱一步步教厨师怎么做。"敲代码"就是把"点这个按钮 → 弹出付款页"用电脑听得懂的话写清楚。
程序 / 软件 / 应用（App）
一堆代码打包成的成品，专干某件事。微信、抖音、淘宝、计算器都是 App；电脑上的 Word、浏览器也是软件。
服务器
机房里一台 24 小时不关机、同时伺候千万人的"超级电脑"。刷视频、抢车票背后都是它；"服务器崩了 / 维护中"就是它忙不过来或坏了，大家一起打不开。
云 / 云端
把照片、文件存到"网上的服务器"而不是手机里，换新手机一登录东西还在。iCloud、百度网盘、"存到云上"就是它。
数据 / 大数据
被记录的各种信息：订单、点过的赞、看过的视频。"大数据"=海量信息攒一起找规律，比如发现"买尿布的人也爱买啤酒"。
算法
一套"怎么做决定"的规则。抖音按你看了啥、停多久，算出下一条推什么；"被算法推送""大数据杀熟"都是它。
人工智能 / AI / 大模型
让电脑像人一样听懂话、写文章、认图。"大模型"是特别会聊天写作的那类，像 ChatGPT、豆包，问一句能写一整篇。
流量
上网的"数据用量"，看高清视频特别费（"这月流量超了"）；也指访问量，"这条视频流量大"=看的人多。

常听到的"形态 / 部位"

客户端 / 网页版 / 小程序
同一个服务的三种打开方式：客户端=要下载安装的 App，网页版=浏览器直接开，小程序=微信里点开即用、不用装。
后台
用户看不见、在背后干活或管理的部分。"切到后台还在下载""商家在后台改价格"——看不到但在运行。
用户体验 / UI
UI=你看到的界面长啥样（按钮、配色、排版）；用户体验=用起来顺不顺手。"这 App 体验好"=找东西不费劲。

常听到的"毛病 & 安全"

Bug（"有个 bug"）
程序里的毛病，不照你想的来。"这有个 bug"="这儿坏了 / 不对劲"。
崩溃 / 闪退 / 卡死
用着用着突然自己退出（闪退），或彻底卡住不动（卡死）。
死机 / 宕机
整台设备或服务器停住、毫无反应。服务器宕机，所有人一起用不了。
缓存（"清一下缓存"）
临时存的一份数据让下次更快；页面显示不对、加载不出来时，"清缓存"常一下就好。
漏洞
程序的安全"缺口"，相当于门没锁好，可能被人钻进来。
病毒 / 木马
偷偷装进设备、搞破坏或偷信息（账号、银行卡）的坏程序。
黑客
专门找漏洞钻进系统的人，可能偷数据、改东西、搞破坏。

常听到的"动作 / 阶段"

上线
把做好的东西正式发布、所有人都能用了。"新功能明天上线"。
更新 / 升级
发布改进后的新版本，修毛病、加功能。手机总提示"有可用更新"就是它。
版本（"最新版""老版本"）
软件的不同阶段，号越大通常越新。"升到最新版""我还是老版本"。
内测 / 公测
正式开放前先小范围试（内测），再放给更多人试（公测），边用边改。游戏常这么干。
兼容 / 不兼容
两个东西能不能一起正常用。老手机"不兼容"新系统=装不了或会出问题。
开源
把代码公开，谁都能看、能用、能帮着改。很多免费软件就是开源的。
需求（"提 / 改需求"）
想让软件做到的事。"客户又改需求了"=又想加 / 改功能了。

常听到的"人"

程序员（码农 / 程序猿）
写代码、把东西真正做出来的人。
产品经理
想清楚"要做成什么样、先做哪个"，把需求理清交给程序员的人。
测试
发布前专门"挑刺"、各种点法都试一遍、把 bug 找出来的人。
运维
盯服务器、保证它 24 小时不出事的人；半夜宕机被叫起来的常是他们。
