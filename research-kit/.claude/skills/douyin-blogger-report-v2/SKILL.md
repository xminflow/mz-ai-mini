# 抖音博主深度方法论拆解（全景版）

读取一个博主已经采集好的全部素材（profile.json + 各作品 meta.json/transcript.txt/帧画面），输出**一份 HTML 全景拆解报告**：

- `<output_dir>/overview.html`：博主全景深度拆解（14 章 + 风险 + 借鉴清单）
- `<output_dir>/index.json`：产物索引

**本 skill 不再生成单作品深度拆解**——代表作品的单条拆解由独立的"单作品拆解 skill"负责。本 skill 聚焦于"博主整体"这个对象，把它拆得深、拆得全。

报告同时回答三个核心问题：

> 1. ta 跑出来的核心招式是什么？
> 2. 这套招式背后绑定了哪些**可识别的运营框架**（《微域生光》方法论体系的哪些点）？
> 3. 同类创作者怎么把这套招式吸收成自己的能力？

## Step 1 · 用 Bash 调用 Python CLI 采集

### 1.1 确定 workspace 路径

从主页 URL 中解析 `sec_uid`（`/user/<sec_uid>` 路径段）作为 blogger_slug。

```bash
WORKSPACE="output/bloggers/<blogger_slug>/raw"
RUN_ID=$(date -u +%Y%m%dT%H%M%SZ)
```

### 1.2 调用 collect 命令

```bash
uv run research-kit collect \
  --url "<完整博主主页 URL>" \
  --workspace "<WORKSPACE>" \
  --run-id "<RUN_ID>" \
  --sample-count 0 \
  --user-data-dir .cache/douyin-profile
```

关键参数：

- `--url`：博主主页 URL，原样传入。
- `--workspace`：固定 `output/bloggers/<blogger_slug>/raw`。
- `--sample-count 0`：按总作品数自动计算（10-20 区间）。如用户明确指定 K 条，传具体数字。
- `--user-data-dir .cache/douyin-profile`：复用已登录的 Chromium 用户目录。首次跑时浏览器会要求扫码登录。
- 重试机制：HTTP 403 已自动重试 3 次 + 3-6s 退避，无需额外处理。
- 幂等：workspace 已完整的作品目录自动跳过，第二次跑同 workspace 只补失败的作品。

### 1.3 解析 CLI 输出

CLI stdout 末尾输出 JSON 摘要，例如：

```json
{
  "ok": true,
  "blogger_id": "MS4wL...",
  "display_name": "晓辉博士",
  "workspace": "/abs/path/output/bloggers/<blogger_slug>/raw",
  "total_works": 370,
  "samples_collected": 18,
  "samples_failed": 2,
  "failures": [...]
}
```

确认：

- `ok=true`
- `samples_collected >= 5`（少于 5 条不足以做 14 章拆解，告知用户失败原因）
- 记下 `blogger_id` 和 `workspace`

### 1.4 失败处理

- "需要登录" → 提示用户用 export-cookies skill 或直接在 `--user-data-dir .cache/douyin-profile` 里登录
- "主页改版/解析失败" → 报错等待 DOM 选择器修复
- 部分 HTTP 403 / SSL 失败 → 重试已用尽，可以接受（10-30% 失败率正常）
- **如果完整作品 < 5 条**，**不要**继续 Step 2。建议用户重跑（已采的作品会幂等保留）。

## Step 2 · 读素材 + 应用 14 章判定框架

### 2.1 读素材

```
WORKSPACE/
├── profile.json           # 必读
├── sampling.json          # 可参考
├── <aweme_id>/
│   ├── meta.json          # 必读
│   ├── transcript.txt     # 必读（可能为空 / null）
│   └── 1.jpg ~ 4.jpg      # 必读（视觉理解）
```

**通读所有作品**（不再"挑选代表作品"，单作品拆解由其它 skill 负责）：

- 每条 meta.json 都读
- 每条 transcript.txt 都读
- 每条画面 1-4.jpg 都用 Read 工具加载（Claude 视觉理解）
- 按 `position` 字段排序，识别早期 / 中期 / 近期作品分布

### 2.2 排序与初步归类

- 按 `position` 排序：position 越小越近期
- 大致划分早期 / 中期 / 近期三段（粉丝量级 + 时间维度）
- 识别哪些作品有完整口播文案、哪些只有标题、哪些没有可读文案

### 2.3 应用 14 章判定框架

下面定义 14 章的判定要求。**每章末有"必须答的问题"清单**——这是深度的硬底线。

---

## 14 章判定框架详解

### 第一章 · 博主画像

**框架来源**：《序言》《第一篇·底层逻辑》三种经济模型 + 8 个伪命题。

**判定要点**：

- **基础画像**：2-4 段自然文。是谁、什么量级、简介透露的定位、近一年作品大致覆盖了哪些维度。**不要写"本次采样 N 条 / 覆盖了 N 条样本"**——读者不需要看到我们的工程口径。
- **博主背景考据**：从作品口播原文里能挖出的真实身份信息（专业背景、行业经历、年龄段大致、性别角色、地域、孩子等）。这些信息是"复制门槛"的核心。
- **一句话答卷**：用一句话讲清核心招式，必须具体到动作。
- **经济模式判定**：流量经济 / 粉丝经济 / 品牌经济 之一 + 判别依据。
- **稀缺线判断**：是否越过书里的"稀缺线"？给至少 2 条作品证据。
- **8 个伪命题自检**：博主有没有陷在书里反复纠错的 8 个伪命题（养号 / 黄金时间 / 日更 / 简化垂直 / 第一条爆款 / 限流 / 标题封面万能 / 追热点万能）？指出博主是否清醒于这些误区。

**必须答的问题**：

1. ta 是谁？真实身份的哪些信息能从作品里挖到？
2. ta 的核心招式用一句话怎么概括？
3. ta 处在哪种经济模式？为什么？
4. ta 已越过稀缺线了吗？凭什么？
5. ta 有没有陷在某个伪命题里？

---

### 第二章 · 观众画像与心理任务

**框架来源**：《第二篇·定位》目标受众分析 + 用户心理任务理论。

**判定要点**：

- **目标受众具体画像**：年龄段、身份、当下处境、焦虑、欲望。不要写"成年女性"这种宽泛，要写"刚晋升中层的 30-40 岁高知职场女性 + 有娃 + 长期被 AI 工具广告轰炸"这种具体画像。
- **8 种用户心理任务识别**：观众把这类内容当成什么来用？从下面 8 种识别 1-3 种主导：
  - 求安慰（情绪疏导）
  - 求判断（拿不准的事让博主告诉答案）
  - 求身份认同（"原来还有人跟我一样"）
  - 求避坑（不知道但会踩的雷）
  - 求效率（生产力提升）
  - 求谈资（饭桌、社交、转发素材）
  - 求陪伴（孤独时刻的人声）
  - 求一个替自己说话的人（说出自己心里说不出口的话）
- **停留、关注、复看、转发的具体动机**：观众为什么在这个博主的内容里**停留**？看完为什么**关注**？关注后为什么**复看**？复看的人为什么**转发**？四个动作背后的心理机制可能不同，要分别答。

**必须答的问题**：

1. 真正的受众画像具体到什么程度？
2. 主导的心理任务是哪 1-3 种？
3. 让观众"看完"的钩子是什么？
4. 让观众"关注"的钩子是什么？（跟看完是两件事）
5. 让铁粉"复看 / 转发"的钩子是什么？

---

### 第三章 · 内容定位

**框架来源**：《第二篇·定位》3+4+3 体系 + 6 大优势自检。

**判定要点**：

- **三位一体**：商业定位 × 内容定位 × 人设定位（三项都要有判断，每项给证据）。
- **商业定位四阶梯**：单品 / 单品类 / 赛道 / 全品类 之一，给出"为什么是这一级，不是上下相邻级"的判断。
- **内容定位三原则**：多维 / 原生 / 高频，逐项给"达成 / 部分 / 未达成"+证据。
- **等号是否立住**：在用户认知里"某类需求 = 这个博主名字"等号成立到什么程度？
- **6 大优势自检**（书里"占任意 2 项就值得做，占 4 项以上立刻开始"）：博主用到了哪些？
  - 客观三项：① 原产地 ② 生产工厂 ③ 实体店
  - 主观三项：④ 会干活（专业手艺过硬） ⑤ 行业有厚度（能连答三层） ⑥ 说话大大方方（镜头前不畏缩）

**必须答的问题**：

1. 三位一体里哪一项最强？哪一项最弱？
2. 商业定位处在哪一阶梯？跨阶梯升级要补什么？
3. 三原则里哪条没达成？该怎么补？
4. 6 大优势里 ta 占了几条？没占到的那几条是真的没有还是没在用？
5. 等号立没立住？立在了哪个具体圈层里？

---

### 第四章 · 作品风格

**框架来源**：《第五篇·拍摄剪辑》视觉语言 + 叙述节奏 + 高频符号。

**判定要点**：

#### 4.1 视觉语言

基于画面素材分析：色调 / 构图 / 人物是否在场 / 场景是否固定 / 字幕位置 / 画面密度 / 镜头变化 / 道具或空间特征。**至少自然引用 2 条作品**。每个视觉判断都要顺手解释：这种视觉选择是在帮助理解、建立信任、制造停留，还是强化账号记忆点。**强烈建议**在本节用 `frame-grid` 内嵌 1–2 张已抓取画面（`data-rk-frame="<aweme_id>/N.jpg"`，publish 阶段会自动上传 COS 并改写 src），让读者直接看到判断证据——这是全报告最值得配图的章节。

#### 4.2 叙述与语言

基于有口播文案的作品分析：口头禅 / 起手式 / 句式节奏 / 口语化程度 / 是否有方言或固定表达。**至少引用 2 句原话**。不要只描述语言表面特征，要落到这些表达是如何降低理解门槛、制造对话感、塑造立场或推动情绪的。

#### 4.3 节奏与内容承诺

分析作品如何在开头给出承诺或问题，中段如何兑现，结尾如何落点。这里要回答：为什么观众不容易划走，以及观众为什么会觉得这条没白看。

#### 4.4 账号记忆点 / 高频符号

写清这个账号被记住的具体符号：固定句式 / 固定开场 / 固定收尾 / 固定场景 / 声音 / 表情 / 字幕习惯 / 道具 / 标题习惯。每个判断都要有作品依据。

**必须答的问题**：

1. ta 的视觉锤是什么？（一秒能让人认出来的视觉元素）
2. ta 的文字钉是什么？（一句能让人重复说出来的口头表达）
3. ta 的开场和收尾有没有固定模板？
4. ta 的内容承诺通常是什么？通常怎么兑现？
5. 如果只能保留一个记忆符号，会保留哪个？为什么？

---

### 第五章 · 核心价值主张

**框架来源**：《第二篇·定位》价值定位 + 信任来源分析。

**判定要点**：

#### 5.1 价值类型

判断情绪价值 / 信息价值 / 实用价值 谁是主、谁是辅。不要写抽象占比，可以写"它表面上提供 X，真正让人留下的是 Y"。

#### 5.2 一句话价值定位

写清观众看完一条作品能带走什么：一个判断、一个情绪出口、一套做法、一种身份认同、还是一个可转述的观点。

#### 5.3 信任来源

分析观众为什么愿意相信 ta：专业身份 / 亲历经验 / 细节密度 / 口吻克制 / 人设稳定 / 长期一致 / 敢说别人不说的话。**至少用 2 条作品作证据**。这一节不要写成人设标签列表，而要写成"信任是如何被持续确认"的过程。

#### 5.4 商业化转化路径推断

分析这个账号最终在为哪种转化铺路：带货 / 引流 / 私域 / 课程 / 咨询 / 广告位 / 品牌合作。不要硬猜成交数据，但要从选题、表达、主页承接和内容结构推断它的转化方向。除了判断"转什么"，还要尽量判断"内容是怎么一步步把人送到这个转化动作前"的。

**必须答的问题**：

1. 三类价值里哪类是真正让人留下来的？
2. 观众看完一条最多带走一样东西，是哪样？
3. 信任是怎么"被持续确认"的？至少给一个过程描述。
4. 商业化转化路径走的哪条？内容是怎么把人引向那个路径的？
5. 如果让 ta 突然提高客单价 10 倍，现在的内容支撑得起吗？

### 第六章 · 选题策略

**框架来源**：《第三篇·选题与素材库》五方向 + 八大爆款元素 + 情绪波点四出口。

**判定要点**：

#### 6.1 选题五方向归类

归到下面五个方向中的一或多个，给出占比的体感判断（主力 / 次要 / 偶发）：

- **找痛点**：用户已在抱怨的事
- **找疑问**：用户拿不准的事
- **找坑**：用户不知但会踩的事
- **找盲区**：用户根本想不到的事
- **找泛话题**：把行业拉进生活的事

#### 6.2 情绪波点四出口（新增）

书里讲"灵感不在外面，在愣神的那一刻"——同一个情绪波点可以走四个创作出口。识别博主**最常用的"灵感来源类型"**：

- **回忆 → 讲故事**：想起当年某件事
- **行动 → 晒过程**：现在就想做点什么
- **分析 → 教知识 / 聊观点**：想理性说点什么
- **愣神 → 聊观点 / 讲故事**：突然在想一件事

不同博主在不同象限里取材。这是判断博主"灵感供给系统"的内核维度。

#### 6.3 八大爆款元素打分

对全部作品集体打分，用表格列出 8 大元素 + "是否常用" + "典型作品"：

| 爆款元素 | 是否常用 | 典型作品与作用机制 |
|---------|---------|-------------------|
| 成本 | … | … |
| 人群 | … | … |
| 猎奇 | … | … |
| 反差 | … | … |
| 最差 | … | … |
| 怀旧 | … | … |
| 荷尔蒙 | … | … |
| 头牌 | … | … |

总结：**这位博主的"招牌火种"是 X + Y 的组合**（一般 1-2 个最有效，不是 8 个都用）。

#### 6.4 选题供给系统

输入源 / 变体规则 / 复用边界：

- **输入源**：个人经历 / 行业痛点 / 评论区提问 / 热点借势 / 固定母题变体 / 混合供给
- **变体规则**：同一母题如何换壳？（换主角 / 换场景 / 换冲突 / 换结论）
- **复用边界**：哪种变体会让观众疲劳？

**必须答的问题**：

1. 五方向里哪条是主力？为什么？
2. 情绪波点四出口里 ta 最常用哪个？这透露 ta 是哪种类型的创作者？
3. 8 大爆款元素里 ta 的招牌火种是哪 1-2 个？
4. ta 的选题输入源是什么？会不会断粮？
5. 同行抄了 ta 的火种但少了什么会立刻露馅？

### 第七章 · 文案与脚本

**框架来源**：《第四篇·上·文案》起承转合 + 五开头 + 五大结构 + 信息密度 + 《第四篇·下·脚本》四型脚本 + 六大论据库。

**判定要点**：

#### 7.1 起承转合与小火车模型

判断博主作品是否符合标准起承转合。每条作品套用「车头 → 车身（N 节） → 车尾」做切片分析：

- 黄金三秒车头给的是什么钩子？
- 中段车身切片密度（每 3-5 秒一个新刺激？每 10-20 秒一个新论点？还是大段口播？）
- 车尾是金句 / 反问 / 悬念 / 留白 / 反转回扣 / 行动建议？

#### 7.2 黄金三秒钩子模板识别

列 2-4 个反复出现的钩子模板，每个套用书里五开头之一（怀旧 / 反差 / 悬念 / 观点 / 共鸣），先写抽象句式，再给作品例证。

每个模板还要回答：抓住了什么情绪 / 认知缺口、内容靠什么动作推进、为什么这种钩子适合**这个账号**而不是所有人都适用。

#### 7.3 五大结构识别（新增）

书里讲五大结构 + 小火车模型。识别博主**最常用的叙述结构**：

| 结构类型 | 特点 | 配套 |
|---------|------|------|
| 分类式 | 列举类似项（"三种 X" / "五个 Y"） | 递进排序，情绪上升 |
| 递进式 | 从简到复、从浅到深 | 每层都往上拱 |
| 对比式 | A vs B，制造张力 | 两边有明显权重差 |
| 故事式 | 设置冲突 → 解决冲突 | 中间必须有跌宕起伏 |
| 实验式 | 做一个事 → 看结果 | 过程要有节奏切片 |

#### 7.4 信息密度三级（新增）

按书里的分级评估博主的密度档位：

| 密度档位 | 表现 | 对应播放量级 |
|---------|------|-----------|
| 低密度 | 3 分钟讲一件事，结论开头就讲 | 三位数 |
| 高密度 | 3 分钟切 10 个片段，每段新刺激 | 五位数~六位数 |
| 超高密度 | 时间轴极致切片 + 空间多层感官 | 七位数~八位数 |

#### 7.5 四型脚本分布

识别博主在四型脚本里的占比 + 是否匹配账号阶段：

| 脚本类型 | 留人逻辑 | 适配阶段 | 该博主占比体感 |
|---------|---------|---------|---------------|
| 聊观点 | 情绪共鸣 | 万粉以上 | … |
| 教知识 | 获得感 | 0→1 万粉起号期 | … |
| 讲故事 | 爽点 | 有信任根基后 | … |
| 晒过程 | 期待感 | 有产品/手艺/店 | … |

#### 7.6 六大论据库（观点型专用）

如果博主大量做观点型，识别 ta 偏爱书里的哪几类论据：

- 权衡利弊（最稳的论据）
- 无奈之举（给他找台阶）
- 不同视角（换角度重新看）
- 人身攻击（只对"幻想中的人"安全使用）
- 倒打一耙（不讲事实，舒服心情）
- 维度升级（从历史/未来/社会大背景看）

**必须答的问题**：

1. 黄金三秒主要靠哪几个钩子模板？

5. 如果是观点型，论据偏好暴露了什么人设特征？

### 第八章 · 制作品质

**框架来源**：《第五篇·拍摄剪辑》拍摄方式 + 三优先级。

**判定要点**：

#### 8.1 拍摄方式归类

| 拍摄方式 | 特征 | 适配 |

### 第九章 · 算法适配

**框架来源**：《第六篇·算法投放》算法四模块 + 完播三维 + 阶段重点 + 5 个反共识"不要"。

**判定要点**：

#### 9.1 标签清晰度推断

从内容词频、选题集中度、画面一致性推断算法把博主识别成什么：

#### 9.2 完播曲线推断（不编数字）

- 开头是否有强钩子（前 5 秒留存）？
- 中段切片密度（中段曲线平整度）？

#### 9.3 阶段重点匹配

| 阶段 | 粉丝量 | 最大瓶颈 | 优化重点 |
|------|--------|---------|---------|
| 起号 | 0-1 万 | 账号被理解 | 标签清晰、选题垂直、频次稳定 |
| 加速 | 1-10 万 | 内容品质 | 完播率、单条突破、爆款元素 |
| 成熟 | 10 万+ | 粉丝转化 | 变现链路、私域承接、直播转化 |

#### 9.4 五个反共识"不要"自检（新增）

书里讲了 5 个被滥用的优化动作，每个都"不要做"。检查博主**有没有错踩**：

- **不要养号** —— 第一条就发最好的
- **不要研究黄金时间** —— 好内容什么时候发都推
- **不要频繁改描述 / 话题** —— 改的瞬间算法重新识别
- **不要刷互动** —— 平台识别能力强，反而贬低权重
- **不要同时发多个赛道** —— 搞乱标签

如果博主有明显踩坑，点出来。

#### 9.5 双池叠加风险（如果二级标签是两个）

如果博主二级标签是双重（如"AI 工具 + 个人成长"），算法会同时推给两个池子的用户。这是机会也是风险——任一池画像漂移都会拖累整体。给出具体的稳定与漂移建议。

**必须答的问题**：

2. 完播曲线大致是什么形状？最弱的位置在哪一秒？
3. ta 处在什么阶段？阶段重点匹配上了吗？
4. ta 有没有踩"5 个不要"中的某一个？
5. 双池叠加风险存在吗？

### 第十章 · 成长路线

**框架来源**：《第二篇·定位》动态调整 + 选题供给系统演化。

**判定要点**：按作品发布顺序分早期 / 中期 / 近期做对比，重点解释"哪些东西被保留，哪些被淘汰，为什么这些变化让账号更稳定"。**强烈建议**用 `frame-grid` 配 1 张早期画面 + 1 张近期画面做视觉对照（直接引用 `data-rk-frame="<aweme_id>/N.jpg"`，publish 阶段会自动上传 COS 并改写 src，无需额外处理）。

#### 10.3 近期作品

写清账号的选题是怎么持续长出来的：是反复换壳讲同一母题，还是确实有稳定的题材供给系统？输入源在 1 年时间里有没有变化？

**必须答的问题**：

### 第十一章 · 变现路径

**框架来源**：《第七篇·变现与商业模式》变现四原则 + 链路五层 + 4P + 10 例失败 + 《番外卷》行业归属。

**判定要点**：

#### 11.1 变现方式识别

- 卖货 / 引流 / 广告 / 打赏，主推哪个，给证据

#### 11.2 变现四原则评估

逐项打分（强 / 一般 / 弱）+ 理由：

- 离钱越近越好（帮赚钱 / 避损 / 省钱）
- 路径越短越好
- 痛点越痛越好
- 边际成本越低越好

#### 11.3 变现链路五层完整度

逐层评估（完整 / 部分 / 缺失）：

1. 内容吸引（流量入口）
2. 信任建立（视频库 + 私域预热）
3. 产品呈现（钩子 + 主力分层）
4. 转化承接（直播 / 私域 / 咨询）
5. 复购维持（会员体系 / 周期触达）

#### 11.4 4P 带货评估（新增）

即使博主没带货，也评估"如果你要带货，4P 会怎样"：

- **Product** · 该博主能卖什么品？匹配人设的是什么？
- **Price** · 客单价区间应该在哪？为什么？
- **Promotion** · 痛点话术应该围绕哪 1-2 个具体场景？
- **Place** · 主力渠道应该是小黄车 / 直播 / 私域哪一条？

#### 11.5 10 例失败模式自检（新增）

书里讲了 10 例变现失败模式，检查博主有没有踩：

1. 先做内容后考虑变现（流量错位）
2. 卖的产品跟账号定位无关（人货不配）
3. 变现链路超过 3 个环节（转化率断崖）
4. 只做卖货不做引流（客单价被限制）
5. 变现文案和内容文案逻辑不一致（割粉丝）
6. 引流后没有承接体系（流量浪费）
7. 试图同时做多种变现方式（每个都没做透）
8. 客单价突然跳变（信任未建立就上高价）
9. 没建立复购机制（一次性收割）
10. 把账号矩阵化太早（精力分散）

#### 11.6 行业归属（按变现结构）

归到番外卷五大行业之一：

- 本地实体（现场履约）
- 专业人士（话语权前置）
- 教育培训（焦虑驱动）
- 实物零售（供应链厚度）
- 数字产品（内容资产复利）

#### 11.7 产品阶梯设计建议（新增）

针对该博主的人设和内容，**给出具体的产品阶梯建议**：

- 9.9-39.9 元钩子产品建议是什么？
- 99-499 元主力产品建议是什么？
- 999-1999 元高端建议是什么？
- 3999+ 元顾问级建议是什么？

不要写空泛"做课"，要写"做什么主题的课，用什么作品作为钩子内容池"。

**必须答的问题**：

1. ta 现在的变现路径是什么？走通了几层？
2. 四原则里最弱的是哪一项？怎么补？
3. 10 例失败模式里 ta 踩了哪几个？
4. 4P 里如果开始带货，最具体应该卖什么、什么价位？
5. 9.9 元钩子产品现在能上线吗？

### 3.4 #summary 必备结构（博主名片 + 一句话答卷）

`<section id="summary">` 必须**只**包含三块内容，按这个顺序：

1. **博主名片**（必填，缺一不算合格）
   - 左：头像 `<img data-rk-frame="avatar.jpg">`，圆形，96–112px
   - 右：
     - `<h1>` 昵称（Alibaba PuHuiTi · Bold，通过 `.font-serif-zh` class 自动套用）
     - 元信息一行（mono）：`抖音号 <span class="text-report">meiple</span>` · `<a target="_blank" rel="noopener noreferrer">访问主页 ↗</a>`（href 透传 `profile.json.home_url`，必填，文字颜色用 `text-report`；若 `profile.json.douyin_id` 末尾误带由 `IP属地` 粘连产生的 `IP`，必须先清理后再写入报告）
     - 完整个人简介（透传 profile.json.description，保留 emoji / @提及 / #话题）
2. **Stats 矩阵**（4 列，必填）：
   - Followers · 粉丝（来自 `follower_count`）
   - Likes · 获赞（来自 `liked_count`）
   - Works · 作品（来自 `total_works_count`）
   - Following · 关注（来自 `following_count`）
   - 大数自动转换为"万 / 亿"展示（例如 413000 → 41.3万；1365000 → 136.5万），数值 `null` 时显示 `—`
3. **一句话答卷**（沿用现有模板）

**禁止**在 `#summary` 出现：
- 任何 eyebrow / 副标题小字（例如 `ANALYSIS · DOUYIN BLOGGER · FULL FRAME`、`Analysis Report v0.3` 等）
- 内部流程元信息——"本次采样 N 条""共 N 条作品入选""读取 N 张关键帧""转录引擎"等任何暴露我们怎么拿到素材的句子，**一律禁止**
- 生成器水印 / 脚注式说明
- 任何指向报告生成过程而非博主本人的描述

### 3.5 左侧固定目录（xl+）+ 行内目录（小屏）

```
  </aside>

  <main class="mx-auto max-w-3xl px-6 pt-14 pb-24 xl:mx-0 xl:px-10">

    <!-- 小屏行内目录：xl+ 隐藏，避免与左侧 sidebar 重复 -->
    <nav class="… xl:hidden">…</nav>

```

要点：
- **不允许**写"Weelume · 博主拆解 / Analysis Report v0.3"之类的顶部 sticky header / badge bar。报告从博主名片开始。
- 左侧 `<aside>` 用 `sticky top-0`、`max-h-screen` 跟随滚动并限制视口高度。

```json
    "avatar_path": "<必填：从 profile.json.avatar_path 透传，相对 workspace 的本地路径，例如 'avatar.jpg'>",
```

#### `blogger.avatar_url` + `blogger.avatar_path` 规则

- **数据来源**：`<workspace>/profile.json` 的 `avatar_url` 与 `avatar_path` 两个字段，都由 collector 写入。
  - `avatar_url`：抖音 CDN 上的远端地址，**仅作"原始来源溯源"留档**，绝对不允许出现在 HTML 报告的 `<img src=...>` 里。
  - `avatar_path`：collector 已经把头像下载到 `<workspace>/avatar.jpg`，写入相对路径 `"avatar.jpg"`。**官网部署和 HTML 报告唯一允许的头像来源**就是这个本地文件（publish 阶段会上传 COS 并改写 src，详见 §Step 4）。
- **必填**：透传两个字段。
- 如果 `profile.json` 里 `avatar_url` 为 `null`：说明 collector 这一次没抓到头像（DOM 改版或登录态失效）。`avatar_path` 同时也是 `null`。**禁止编造**——`index.json` 的两个字段都设为 `null`，HTML 报告按 3.3 节的首字母占位方案处理，并在 `summary` 章节加 `<!-- WARN: 头像未抓到 -->` 提示重跑 collector。
- 如果 `avatar_url` 有值但 `avatar_path` 为 `null`：说明 collector 抓到了 URL 但下载失败（网络问题）。仍然**不允许**外链 `avatar_url` 兜底——HTML 报告按 3.3 节首字母占位处理，并在产物里加 `<!-- WARN: 头像本地化失败，使用首字母占位 -->`。下次重跑 collector 可以补齐本地文件。

#### `blogger.description` 规则

- **数据来源**：`<workspace>/profile.json` 的 `description` 字段（由 collector hover 展开按钮后抓取）。
- **首选**：直接透传 profile.json 的原文，**保留所有 emoji、换行、@提及、#话题**。
- **fallback**：仅当 `profile.json.description` 为 `null` 时，允许 LLM 基于**已有作品素材**（昵称、作品标题、口播文案、运营手册风格信号）写一句 ≤60 字的方法论侧写填入。
  - 必须以 `[未抓到原始简介 · LLM 推断]` 作前缀，让二次阅读者知道这是推断不是事实。
  - 推断内容必须可被作品素材证伪——禁止虚构身份、职业、机构、所在地等"无证据外推"信息。
- 禁止把 `description` 写成空串。要么是原文，要么是 `[未抓到原始简介 · LLM 推断] xxx`，要么是 `null`（极端情况：连 fallback 都无法写）。

**不再有 `videos` 数组**。

## Step 4 · 不做图片处理，占位符原样保留

> **v0.4 改动**：原先 Step 4 把图片转 base64 内嵌到 HTML，导致单份报告膨胀到 600 KB+。
> 现在图片走腾讯云 COS：**skill 生成阶段保持 `data-rk-frame="<rel>"` 占位符不变**，
> 由 `research-kit publish` 命令在上传后端时自动扫描占位符、上传 COS、改写为 `src="<cos url>"`。

### 4.1 skill 终止条件

skill 完成后只需验证：

```bash
# overview.html 里仍有 data-rk-frame 占位符是正常的
grep -c 'data-rk-frame=' output/bloggers/<blogger_slug>/reports/<run_id>/overview.html
# 应返回 ≥ 1（至少有 avatar）
```

**不要**自己跑任何 base64 / 上传脚本。

### 4.2 报告里只允许两类图片来源

| 来源 | 允许？ | 备注 |
|------|--------|------|
| `<img data-rk-frame="<rel>">` 占位符 | ✓ | 唯一允许的形式 |
| `<img src="https://...cos.../">` 远端 URL | ✗（skill 阶段） | 由 publish 命令统一改写 |
| `<img src="data:image/...;base64,...">` 内嵌 base64 | ✗ | 已废弃 |
| `<img src="https://...douyinpic.com/...">` 抖音 CDN 外链 | ✗ | 永久禁止，URL 会失效 |

如果某条作品没有可用画面，**不要硬贴占位符**——换一条画面齐全的作品作配图。

### 4.3 本地预览

带 `data-rk-frame` 占位符的 HTML 在本地浏览器里**看不到图片**（src 还没改写）。如果只是在本地 review 文字内容，可以接受图位空白。

如果一定要在本地预览图片，有两个办法（**不要把 base64 写回 overview.html**）：

**方案 A · 跑临时 HTTP 服务把整个 workspace 暴露给浏览器**（推荐）：

```bash
cd output/bloggers/<blogger_slug>/raw && uv run python -m http.server 8765 --bind 127.0.0.1
# 然后浏览器开 file:// 形式的 overview.html，但 data-rk-frame 需要先用脚本临时
# 改写成 src="http://127.0.0.1:8765/<rel>"，记得只写到 _preview.html 副本
```

**方案 B · 直接调用 publish 的预览模式**（如果以后加 `--preview` flag）。

### 4.4 publish 阶段做了什么（仅供理解，无需手动操作）

```
research-kit publish --workspace output/bloggers/<blogger_slug> --env prod
   ↓
1. 读 reports/<run_id>/overview.html + index.json + raw/profile.json
2. 扫描 HTML 中所有 data-rk-frame="<rel>" 占位符
3. 每个 <rel> 上传到腾讯云 COS：
   blogger-insights/<slug>/<run_id>/<rel.replace('/', '_')>
   例：avatar.jpg               → blogger-insights/<slug>/<run_id>/avatar.jpg
       7637.../1.jpg            → blogger-insights/<slug>/<run_id>/7637..._1.jpg
4. 把 data-rk-frame="<rel>" 改写为 src="https://<bucket>.cos.<region>.myqcloud.com/<key>"
5. payload.avatar_url 复用 avatar.jpg 的 COS URL（不再 base64）
6. POST 到 /api/v1/blogger-insights/import
```

凭证读取自环境变量 `MZ_AI_CASE_IMPORT_COS_*`（与 server 端共享一份），缺哪个都会硬失败、不静默兜底。

## 写作规则（沿用 v1 + 强化）

### 角色

冷静的内容运营策略师 + 对读者负责的深度作者 + 《微域生光自媒体运营实战》方法论体系的熟练应用者。

### 写作硬约束

1. **每一节都要写因果链**：判断 → 为什么成立 → 证据是什么 → 对同类创作者意味着什么。
2. **每个核心判断都要回答作用机制**：不要只写"有辨识度""节奏好"。
3. **优先跨作品归纳**：风格判断、方法论判断都要建立在多条作品上。
4. **每章都要回答"必须答的问题"**：上面 14 章每章末列出的问题清单是硬底线。
5. **素材不足时降低判断强度**：可以写"从现有作品看""更像是""至少在这一年的作品里"，但不能用猜测把分析补满。**注意**：不要写"在这批样本里 / 从样本看"——这是内部词。
6. **方法论框架是镜子不是模板**：用框架去**判别**博主，不是把框架原文复述一遍。
7. **优先采用书里的术语**：稀缺线、黄金三秒、信息密度、小火车模型、目的垂直手段多维、四型脚本、五开头、八大爆款元素、情绪波点四出口、五大结构、变现四原则、链路五层 —— 保留原汁原味。
8. **报告里不暴露采集机制**：不写"本次采样 N 条""转录引擎""帧 X""sec_uid"等任何透露我们是怎么拿到这些数据的内部词——读者只需要看到"这是一份对博主的深度拆解"。

### 引用规范

- 内部排序可用 `position`，但 HTML 报告**不允许**出现 `#17`、`作品 #<position>`、`pos N` 等内部编号。
- 提炼用户能看懂的短标题（去掉博主名前缀、话题标签和多余标点）。
- 原话引用：`<blockquote>"…"<cite>—— 出自《作品短标题》</cite></blockquote>`
- 标题依据：`（来自《作品短标题》的标题）`
- 画面依据：`（来自《作品短标题》的画面）`
- 跨作品归纳：`（综合《作品 A》《作品 B》《作品 C》）` —— 不要写"多样本归纳"
- 缺口播文案的作品：`（《作品短标题》没有可读的口播文案，这里只基于画面判断）` —— 不要写"缺转录""转录为空"

### 画面配图（鼓励使用）

collector 在每条作品目录下抓了 4 张画面（`<aweme_id>/1.jpg` … `4.jpg`）。这些图**就是报告里的配图素材**——HTML 里用 `data-rk-frame="<aweme_id>/N.jpg"` 占位符引用，publish 命令会上传 COS 并改写为 `src="<cos url>"`，无需手动拷贝或上传。

报告里**鼓励**用这些画面给文字判断配图，让长文有视觉呼吸感。规则：

- **优先使用场景**：
  - 第四章 · 作品风格（视觉语言 / 视觉锤 / 高频符号——直接给图，最有说服力）
  - 第八章 · 制作品质（音质 / 画质 / 表现力的判断需要画面佐证）
  - 第十章 · 成长路线（早期 vs 近期对照——一张早期画面 + 一张近期画面，演化一目了然）
- **每章 ≤ 2 张**：配图是辅助判断、不是装饰，不要把报告塞成画册。
- **必须有 `<figcaption>` 解说**：一句话说明"这张画面在证明什么判断"，把图绑回正文（比如"早期 · 户外手持 + 平头造型"对照"近期 · 固定书房 + 三件套定型"）。
- **alt / figcaption 都不允许出现内部词**：不要写"样本 7600950..."、"pos 0 的画面"、"frame 1"、"第 N 帧"——只写作品短标题 + 视觉描述。
- **缺画面的作品**：不要硬贴占位符（publish 阶段会跳过缺失文件并在日志里 WARN）。如果某条作品的 `<aweme_id>/N.jpg` 不存在，就换一条画面齐全的作品作配图。
- **结构用 `frame-grid`**（template 已内置 CSS）：

  ```html
  <figure class="frame-grid">
    <div>
      <img data-rk-frame="<aweme_id>/1.jpg" alt="《作品短标题》画面" />
      <figcaption>一句话解说，说明这张画面在证明什么判断</figcaption>
    </div>
    <div>
      <img data-rk-frame="<aweme_id>/3.jpg" alt="《另一作品短标题》画面" />
      <figcaption>对照解说</figcaption>
    </div>
  </figure>
  ```

  单张配图也可以——`frame-grid` 是 2 列 grid，只放 1 个 `<div>` 会自然居左占一格；想居中可改用 `<figure>` 直接包一张 `<img data-rk-frame="..."/>` + `<figcaption>`，CSS 走默认即可。

### 禁用术语（写进 HTML 报告里就算违规）

报告是面向博主本人 / 同行 / 客户的成品文本，**所有暴露"我们怎么拿到这些素材"的内部词汇都必须改写**。

| 类别 | 禁用词 | 改写成 |
|------|------|------|
| 内部流程词 | `采样`、`采样作品`、`本次采样`、`采集`、`采集到`、`抓取`、`爬取`、`抓取到` | 直接谈"作品"，不要再提"我们怎么拿到的" |
| 内部素材词 | `转录`、`转录文本`、`转录文案`、`音频转录` | `口播`、`口播原文`、`原话`、`视频文案` |
| 内部数据词 | `样本`、`样本量`、`这批样本`、`样本证据`、`跨样本`、`样本数` | `作品`、`这批作品`、`作品证据`、`跨作品` |
| 内部位置词 | `#17`、`#3`、`作品 #<position>`、`position`、`pos N` | 用作品短标题，按需配"早期 / 中期 / 近期"修饰 |
| 帧 / 画面术语 | `帧`、`关键帧`、`第 N 帧`、`frame`、`抽帧`、`基于 K 张帧` | `画面素材`、`画面`、`镜头`（必要时） |
| 文件 / 字段名 | `transcript: null`、`meta.json`、`profile.json`、`sampling.json`、`workspace`、`aweme_id`、`sec_uid`、`avatar_path`、`run_id` | 完全不出现——这些是工程产物名，HTML 报告里没有任何引用它们的理由 |
| 引擎 / 工具名 | `FunASR`、`research-kit`、`collector`、`douyin-blogger-report-v2`、`Playwright`、`CDP` | 完全不出现 |
| 吹捧腔 | `封神`、`绝了`、`无敌`、`开挂`、`降维打击` | 去掉，换成可证伪的具体判断 |
| 报告腔 | `本报告`、`本拆解`、`本次分析显示`、`综上所述` | 直接给判断，不自指 |
| 编造数据 | 任何未在公开页面真实存在的播放、点赞、互动、增长、完播指标 | 不写——除非来源是 `profile.json` 里有据可查的字段 |

**自检办法**：写完报告 Ctrl+F 搜一遍上表每个左列词，命中任何一个都必须改写。**特别要搜的高发词**：`样本`、`转录`、`采样`、`采集`、`帧`、`pos`、`position`、`aweme`。

### 算法四模块
识别内容 → 归类聚类 → 反作弊 → 展示排序

### 完播三维度
时长 / 进度 / 领域

### 阶段重点

| 阶段 | 粉丝量 | 重点 |
|------|--------|------|
| 起号 | 0-1 万 | 标签清晰、选题垂直、频次稳定 |
| 加速 | 1-10 万 | 完播率、单条突破、爆款元素 |
| 成熟 | 10 万+ | 变现链路、私域承接、直播转化 |

### 5 个反共识"不要"
不要养号 / 不要研究黄金时间 / 不要频繁改描述 / 不要刷互动 / 不要同时发多赛道

### 变现四原则
离钱近 / 路径短 / 痛点痛 / 边际成本低

### 变现链路五层
内容吸引 → 信任建立 → 产品呈现 → 转化承接 → 复购维持

### 10 例变现失败模式
先做内容后变现 / 货跟人设无关 / 链路超 3 环 / 只卖货不引流 / 文案逻辑不一致 / 引流无承接 / 同时多变现方式 / 客单价突然跳变 / 没建立复购 / 太早矩阵化

### 4P 带货法则
Product · Price · Promotion · Place

### 番外卷五大行业（按变现结构）
本地实体（现场履约） / 专业人士（话语权前置） / 教育培训（焦虑驱动） / 实物零售（供应链厚度） / 数字产品（内容资产复利）

### 3+4+3 定位体系
- **3**（三位一体）：商业定位 × 内容定位 × 人设定位
- **4**（商业四阶梯）：单品 → 单品类 → 赛道 → 全品类
- **3**（内容三原则）：多维 / 原生 / 高频
