# track-research · 采集 agent 执行指南

本文件由 track-research 主 SKILL.md 通过 Agent 工具调用 general-purpose 子 agent 时附在 prompt 里使用。子 agent 启动后**第一件事**就是 Read 本文件，按此执行：先按 §1 判断是否需要澄清关键词，再按 §2 完成 5 维度关键词矩阵 + 白名单分层采集，最终在 `<workspace_dir>/raw/` 下落盘四份产物。整个执行过程**只调用 WebSearch / WebFetch**，禁止启动 Playwright、模拟登录、注入 cookie、抓站外图片。

## 接口契约

**输入**：主 SKILL 会传入以下参数：

- `track_keyword`：用户给出的赛道关键词（可能模糊，模糊时按 §1 询问澄清）
- `region`：地域范围（默认中国大陆）
- `audience`：读者画像（投资人 / 个人创业者 / 大厂业务负责人 / 行业从业者）
- `track_slug`：赛道关键词的拼音连字符化（用作目录名）
- `run_id`：本次跑批的 UTC 时间戳标识，格式 `YYYYMMDDTHHMMSSZ`
- `workspace_dir`：工作区绝对路径（产物全部落在 `<workspace_dir>/raw/` 下）

如果 `track_keyword` 模糊，按本文件 §1 关键词澄清流程问用户；否则跳过 §1 直接进 §2。

**输出**：在 `<workspace_dir>/raw/` 下产出四份产物：

- `sources.json`：所有来源的结构化清单
- `index.md`：5 维度关键词矩阵 + 按站点分组的来源摘要 + 数据缺口章节
- `data_index.md`：4 张关键数据表（核心市场指标 / 标杆玩家 / 成本与收益 / 用户行为）
- `material/*.md`：每一条来源的原文要点（一文一文件）

**完成回报格式**：完成后用一段简短中文回报给主 SKILL，包含：

- 来源总数
- 按等级汇报：S 级 X 条 / A 级 X 条 / B 级 X 条 / C 级 X 条
- 关键 S 级机构清单（如"国家统计局、CNNIC、巨潮资讯"）
- 数据缺口要点（≤ 3 行）
- 四份产物的**绝对路径**

**不要**在回报里贴完整的 material 内容。主 SKILL 会自己 Read。

## §1 关键词澄清（条件触发）

### 1.1 何时触发 / 何时跳过

**触发澄清**（关键词模糊，必须问）：

- 用户只给单一名词（例如「咖啡」「穿搭」「AI 工具」）
- 关键词同时覆盖多个细分赛道（例如「咖啡」可指家用机 / 连锁店 / 咖啡豆电商 / 咖啡内容博主）
- 关键词地域跨度大且差异显著（例如「茶饮」中国 vs 东南亚结构完全不同）
- 关键词的读者画像不明（B 端创业者 / C 端从业者 / 投资人各自要的深度差异大）

**跳过澄清**（关键词已锁定，直接进入 §2）：

- 用户给出复合关键词且 3 维度齐全（例如「家用咖啡机评测内容 + 中国大陆 + 个人内容创业者」）
- 用户上轮已澄清过，本轮要求复跑
- 用户明确说"先跑一版看看"，可放宽到任意细分进入

### 1.2 询问哪 3 个澄清维度

一次性问完 3 个问题（不要逐个问），用清单格式：

1. **聚焦范围**：限定到哪个细分？例如"咖啡"→"家用咖啡机评测内容" / "连锁咖啡店运营" / "咖啡豆电商" / "咖啡相关内容博主"。
2. **地域**：覆盖哪个市场？默认中国大陆。可选：全球 / 中国大陆 / 港澳台 / 东南亚 / 美国 / 欧洲 / 日韩。
3. **读者画像**：报告给谁看？决定语气与深度——投资人（看市场+商业模式） / 个人创业者（看操盘+财务预测） / 大厂业务负责人（看竞争+AI 落地） / 行业从业者（看趋势+差异化空间）。

询问语气：直接列三问，附上"不答完则默认细分=最常见品类、地域=中国大陆、读者=个人创业者"。

### 1.3 锁定 track_keyword / track_slug

澄清完后必须打印锁定结果，例如：

```
track_keyword: 家用咖啡机评测内容
region:        中国大陆
audience:      个人创业者
track_slug:    jiayong-kafeiji-pingce-neirong
run_id:        20260520T083000Z
```

**track_slug 命名规则**：关键词转拼音再连字符。"家用咖啡机评测"→`jiayong-kafeiji-pingce`。中文多音字或拼音冲突时附 4 位 hash 后缀。**禁止**直接用中文做目录名（Windows 路径在 Bash/Python 间传递时容易出问题）。

**run_id 命名**：`YYYYMMDDTHHMMSSZ` UTC。与博主拆解一致。

## §2 采集流程

采集**完全由 Claude 调用 WebSearch / WebFetch 完成**，本 agent 不调用任何 research-kit Python collector、不启动 Playwright、不写入任何 cookie，不做任何模拟登录。

§2 的目标是产出一份"投研级公开素材底稿"：

- `<workspace>/raw/sources.json`：所有来源的结构化清单
- `<workspace>/raw/index.md`：5 维度关键词矩阵 + 按站点分组的来源摘要 + 数据缺口章节
- `<workspace>/raw/data_index.md`：4 张关键数据表（核心市场指标 / 标杆玩家 / 成本与收益 / 用户行为），后续主 SKILL 写报告的**唯一权威数据源**
- `<workspace>/raw/material/<NN>_<site>_<slug>.md`：每一条来源的原文要点（一文一文件）

你不能跳过任何一个产物。主 SKILL 在校验底稿完备性后才会推进到分析阶段。

### §2.1 5 维度关键词矩阵

进入 §2 你做的第一件事：基于 `track_keyword` 衍生 5 维度关键词矩阵，打印给用户**并**写入 `raw/index.md` 头部，作为整个采集阶段的纲领。

每个维度独立搜索，**绝对不要把所有维度拼成一个长查询丢给 WebSearch**——简单拼词会让搜索引擎主题漂移，命中同一类来源，导致最终素材结构失衡。

| 维度 | 含义 | 怎么提炼 | 模板句式 | 「家用咖啡机评测」示例 | 「中老年穿搭」示例 | 「AI 写作工具」示例 |
|---|---|---|---|---|---|---|
| 赛道词 | 最直接的赛道名词，目标是命中行业研究报告与媒体盘点 | 把 `track_keyword` 切成核心名词 + 修饰词 + 同义替换 | `<赛道关键词>`、`<赛道关键词> 评测`、`<赛道关键词> 测评`、`<赛道关键词> 推荐`、`<赛道关键词> 入门` | 家用咖啡机、家用半自动咖啡机、家庭咖啡机、家用意式咖啡机、家用咖啡机推荐 | 中老年穿搭、银发穿搭、奶奶穿搭、爷爷穿搭、中老年时尚 | AI 写作工具、AI 写作助手、智能写作软件、AI 写作生成器、AI 写作 推荐 |
| 行业词 | 该赛道在产业链中的上位品类，目标是命中政府统计 / 行业白皮书 | 沿"产品 → 子行业 → 大行业"上溯 | `<上位品类>`、`<上位品类> 行业报告`、`<上位品类> 市场规模`、`<上位品类> 增速`、`<上位品类> 白皮书` | 小家电 行业报告、厨房电器 市场规模、消费升级 增速、家电零售 白皮书 | 银发经济 市场规模、老龄化消费 行业报告、中老年时尚产业 增速 | 生成式 AI 市场规模、AIGC 行业报告、大语言模型 市场规模、SaaS 白皮书 |
| 场景词 | 用户用这个东西在干什么，目标是命中需求侧定性描述与用户访谈 | 列出 3-5 个真实使用情境 | `<场景> <赛道关键词>`、`<人群> <赛道关键词>`、`<场合> <赛道关键词>` | 居家咖啡 体验、办公室咖啡 推荐、Espresso 入门、咖啡爱好者 装备、咖啡新手 选购 | 中老年 日常穿搭、母亲节穿搭、退休生活 着装、广场舞穿搭、家庭聚会 中老年穿搭 | 公众号 AI 写作、小红书 AI 文案、营销文案 AI、短视频脚本 AI、学术写作 AI |
| 竞品词 | 头部品牌 / 头部账号 / 头部产品的名字，目标是命中竞品深度报道与公开数据 | 先用 WebSearch 搜"`<赛道关键词>` 头部"或"TOP10"拿到候选名单，再逐个独立搜 | `<品牌名> <赛道关键词>`、`<品牌名> 销量`、`<品牌名> 营收`、`<头部账号名> 粉丝量` | 德龙 家用咖啡机、铂富 销量、Breville 评测、小米咖啡机 营收、心想 咖啡机 | 时尚奶奶团 粉丝量、only 中老年女装 营收、抖音中老年穿搭头部博主 | 通义千问 营收、文心一言 用户量、Kimi 融资、秘塔写作猫 评测、Notion AI 用户量 |
| 趋势词 | 增长 / 数据 / 政策 / 投融资关键词，目标是命中"增长曲线 + 投资动向 + 监管信号" | 围绕"增速""融资""政策""KOL"四类语义展开 | `<赛道关键词> 增长`、`<赛道关键词> 销量`、`<赛道关键词> 投融资`、`<赛道关键词> 政策`、`<赛道关键词> KOL` | 咖啡赛道增长、家用咖啡机销量 2024、家用咖啡机 融资、咖啡 KOL、咖啡内容博主 | 银发经济 增长、中老年抖音用户、中老年消费力、银发 KOL、中老年 直播带货 | AIGC 市场规模、AI 写作 渗透率、生成式 AI 投融资、AI 内容 版权、AI 写作 KOL |

操作约束：

- 每个维度至少给出 3 个关键词，可多至 8 个；只给一个空泛词（如只写"咖啡机"）会让 WebSearch 失焦
- 关键词矩阵打印给用户的同时**必须落到 `raw/index.md` 的头部**，作为后续审查时反查"是否漏维度"的依据
- 一个维度搜出来的高质量来源 > 5 条时不必再扩词；< 2 条时必须扩词或调整说法
- 维度之间的来源严禁"复用"——同一篇媒体报道不要既算行业词命中也算趋势词命中，写一次即可

**自检**：在打开 WebSearch 之前，确认 `raw/index.md` 已经写好包含 5 维度关键词矩阵的头部，且每个维度至少 3 个关键词。

### §2.2 权威源四级评级体系（全部免登录可访问）

**全局原则：登录可见的内容，不采集。**

白名单只收录"主要内容完全免登录可见"的站点——只要核心数据/正文需要登录、付费、注册、扫码、订阅或验证码，一律不收录。

#### 评级定义（S / A / B / C 四档）

| 等级 | 性质 | 采集优先级 | 证据强度 | 双源要求 |
|---|---|---|---|---|
| **S** | 法定 / 官方 / 国际机构。政府统计、部委、央行、监管、国际组织、上市公司法定披露 | **必抓** | 直接采信 | **单源可引** |
| **A** | 学术 / 行研 / 咨询。科研院所、官方智库、专业行研机构、四大、国际咨询公司公开报告 | **强烈推荐** | 高 | 建议双源，单源亦可 |
| **B** | 财经 / 产业媒体。深度报道、融资数据库、上市公司新闻 | 按需 | 中 | **必须双源** |
| **C** | 平台 / 参考。电商、关键词趋势、维基百科 | 按需 | 仅辅助 | **禁止单独承担核心论断** |

**采集分配硬底线**（任一不达标必须扩词重搜或换站点）：

- S 级 **≥ 2 个**（其中至少 1 个是中国境内官方机构）
- A 级 **≥ 2 个**（其中至少 1 个是行研机构或智库）
- B 级 **≥ 3 个**（至少 2 家不同媒体，避免单家口径主导）
- C 级 按场景需求，可为 0

#### 触发登录/付费墙怎么办

抓任何 URL 时只要命中 §2.3.2 的五类降级特征里的"登录墙文本"或"跳转登录页"，**立即放弃该来源**，不重试、不绕过、不模拟登录。按 §2.3.3 三选一处理，并在 `raw/index.md` 数据缺口章节诚实标注一行。

不维护具体"禁用站点清单"——规则就是一句："登录可见的内容，不采集"。

#### 简表速查（完整清单见附录 A）

**S 级**（法定 / 官方 / 国际）：国家统计局、央行、工信部、商务部、海关总署、发改委、市场监管总局、药监局、CNNIC、巨潮资讯、港交所披露易、SEC EDGAR、各省统计局、世界银行、IMF、OECD、UN Data、WTO 统计

**A 级**（学术 / 行研 / 咨询）：中国信通院、社科院、国务院发展研究中心、清华/北大经管研究中心、腾讯研究院（tisi.org）、阿里研究院（aliresearch.com）、艾瑞咨询、易观分析、DataEye、IDC China、Gartner（公开版）、Frost & Sullivan、麦肯锡 / BCG / 贝恩公开报告、四大（PwC / Deloitte / EY / KPMG）行业洞察、Statista（公开页）、Stanford HAI AI Index、Our World in Data

**B 级**（财经 / 产业媒体）：36 氪、界面新闻、第一财经、财新（公开稿）、21 世纪经济报道、经济观察报、虎嗅、钛媒体、晚点 LatePost、投资界、Crunchbase（公开基础数据）

**C 级**（平台 / 参考）：京东搜索、淘宝搜索、Google Trends、百度指数（公开页）、中文 / 英文维基百科

**自检**：开始抓任何 B/C 级之前，先确认 S 级 ≥ 2、A 级 ≥ 2 已经覆盖。优先级反了 = 报告会被媒体口径而非官方数据撑场，质量必然崩。

### §2.3 WebSearch / WebFetch 调用模式

整体采集流程：

```
对每个维度（共 5 个）：
  对每个关键词（每维度 3-8 个）：
    WebSearch  → 拿 5-10 个候选 URL
       ↓
    按 §2.2 白名单分层过滤（不在白名单 → 跳过）
       ↓
    WebFetch <url>  → 拿正文 markdown
       ↓
    判断是否触发降级（§2.3.2 五类特征）
       ↓
    通过 → 写入 raw/material/<NN>_<site>_<slug>.md + 追加 sources.json + 在 data_index.md 提取数据
    降级 → 按 §2.3.3 三选一处理 + 记入数据缺口
```

#### §2.3.1 调用范式

WebSearch：

```
WebSearch:
  query: "<赛道关键词> 市场规模 2024"
  domains: [
    // S 级（最高权威）
    "stats.gov.cn", "pbc.gov.cn", "miit.gov.cn", "mofcom.gov.cn", "ndrc.gov.cn",
    "cninfo.com.cn", "hkexnews.hk", "sec.gov", "cnnic.net.cn",
    "worldbank.org", "imf.org", "oecd.org",
    // A 级（学术 / 行研 / 咨询）
    "caict.ac.cn", "cass.cn", "drc.gov.cn",
    "tisi.org", "aliresearch.com",
    "iresearch.com.cn", "analysys.cn", "iimedia.cn", "dataeye.com",
    "idc.com", "gartner.com", "statista.com",
    "mckinsey.com", "bcg.com", "bain.com",
    "pwc.com", "deloitte.com", "ey.com", "kpmg.com",
    "aiindex.stanford.edu", "ourworldindata.org",
    // B 级补充（投融资数据库，公开基础数据）
    "crunchbase.com", "cbinsights.com"
  ]
```

按 §2.2 评级体系填充 domain 优先级——S 级先、A 级次、B/C 级最后。如果 WebSearch 工具不支持 domain 过滤，搜索结果出来后手工按白名单挑选 URL 再传给 WebFetch。

WebFetch：

```
WebFetch:
  url: "http://www.caict.ac.cn/kxyj/qwfb/bps/202403/t20240318_xxxxx.html"
  prompt: "提取以下信息：1) 文章发布时间 2) 中国家用咖啡机 2023-2024 年市场规模与增速 3) 主要厂商市占率 4) 原文核心论断 3 句。原文逐句保留数字与单位。"
```

`prompt` 必须显式列出"要提取什么"，不要让 WebFetch 自由发挥总结一段散文回来——你拿不到原文行号就无法填 `data_index.md` 的"原文出处"字段。

#### §2.3.2 降级触发的五类文本特征

WebFetch 返回内容命中下列任意一类，**立即停手**，进入 §2.3.3 降级处理。不允许重试穿透（重试 = 浪费 token + 给目标站点送压力）。

| 类别 | 触发文本 / 现象 |
|---|---|
| 登录墙文本 | `请登录后查看` / `登录以查看完整内容` / `开通会员` / `开通 PRO` / `注册后可见` / `成为付费用户` / 大段 `*****` 遮罩 |
| 内容截断 | 抓回的正文 < 200 字且明显是摘要尾巴，文末有"查看完整版"按钮 |
| 跳转登录页 | 实际访问 URL 含 `/login`、`/signin`、`/passport`、`/auth/`、`/account/login`、`?redirect=` 参数 |
| JS 渲染失败 | HTML 总长 < 2KB 或核心 `<article>` / `<main>` / 正文区为空，只剩骨架与导航 |
| 主题严重不符 | 抓回的内容与搜索关键词无关（典型：301 跳到首页、404 错误页、广告 / 推广页） |

#### §2.3.3 降级三选一

降级时**禁止重试相同 URL**。三个处理路径，按优先级选：

1. **换关键词重搜**：当只是搜索词不精准（命中"主题不符"）时，换同义词或加限定词再走一次 WebSearch + WebFetch
2. **换替代源**：当目标信息可以从其它免登录站点拿到时，换一家白名单内的站点重搜（同一指标换机构、同一新闻换媒体）
3. **记数据缺口**：当命中"登录墙文本"/"跳转登录页"/"JS 渲染失败"时，在 `raw/index.md` 的「数据缺口」章节加一行；**不**为该来源建 material 文件，**不**在 sources.json 里伪造记录、**不**尝试只摘"页面边角公开部分"凑数

原则：登录可见的内容一律不采集——既不绕过、也不"仅摘公开部分"硬凑。

#### §2.3.4 严禁清单

下列操作在 §2 全程禁止，命中即任务失败：

- 模拟登录（用户名 / 密码 / 验证码任何形式）
- 注入 cookie（包括用户提供的 cookie）
- 任何形式的反爬绕过（修改 UA、代理、IP 轮换、验证码识别）
- 调用 Selenium / Playwright / Puppeteer 模拟点击
- 编造数据补缺口（包括"按行业惯例估算"、"参考同类赛道推测"）
- 用 WebFetch 抓站外图片（PNG / JPEG / WEBP / GIF / SVG）
- 直接复制其它 AI 工具或其它对话的输出当作"来源"

**自检**：每抓完一个 URL，问自己——这条 material 文件里的每个数字，我能不能在原文 URL 打开后逐个找到？如果不能，是不是 WebFetch 在自由总结？必须立即重抓并要求 WebFetch 给出"原文逐句"。

### §2.6 采集验收清单（grep 自检式）

采集完成、向主 SKILL 回报之前，必须逐条自检。**任一项不达标禁止回报完成**，必须补采或主动告知用户"该赛道公开数据深度不足，建议人工介入"。

#### §2.6.1 数量门槛（按 §2.2 四级评级）

| 检查项 | 阈值 | 反查方式 |
|---|---|---|
| 来源总数 | ≥ 15 份 | `raw/sources.json` 的 `sources` 数组长度 ≥ 15 |
| **S 级**（法定 / 官方 / 国际） | ≥ 2 份 | `sources[].grade == "S"` 至少 2 条，且其中至少 1 条 `country == "CN"`（中国境内官方机构）|
| **A 级**（学术 / 行研 / 咨询） | ≥ 2 份 | `sources[].grade == "A"` 至少 2 条，且其中至少 1 条来自智库或行研机构 |
| **B 级**（财经 / 产业媒体） | ≥ 3 份 | `sources[].grade == "B"` 至少 3 条，且至少 2 家不同媒体（避免单家口径主导）|
| **C 级**（平台 / 参考） | 0-不限 | 按场景需求，无强制下限 |
| 头部玩家 / 账号 | ≥ 5 个 | `data_index.md` 表 2 的行数 ≥ 5 |

#### §2.6.2 质量门槛

| 检查项 | 阈值 | 反查方式 |
|---|---|---|
| 关键指标双源验证率 | ≥ 60% | `data_index.md` 表 1（核心市场指标）中"双源"列标 ✅ 的行数 / 总行数 ≥ 0.6。原则：能双源交叉就标 ✅，找不到第二个独立来源就诚实标 ⚠️ 单源——禁止凑双源 |
| 每个来源都有真实 `fetched_at` | 100% | `sources.json` 全量过一遍，`fetched_at` 字段不为空、格式合法 |
| 每个来源都有等级标注 | 100% | `sources[].grade` 必须是 `S` / `A` / `B` / `C` 之一，不允许空或其它值；评级标准见 §2.2 |
| material 文件实际存在 | 100% | `sources[].file` 指向的文件在磁盘存在；反之磁盘上不应有任何 `sources.json` 没记录的 material 文件 |
| 数据缺口章节非空 | 至少 1 条 | `raw/index.md` 的 `## 数据缺口` 章节至少 1 个 bullet，且"已尝试但需登录"的站点都被记录 |

| 检查项 | 反查方式 |
|---|---|
| sources.json ↔ index.md 一致 | sources.json 中每条记录在 index.md 都能找到对应 bullet |
| sources.json ↔ material/ 一致 | sources.json 中每条 `file` 路径对应的 material 文件存在；磁盘上没有"游离"的 material 文件 |

#### §2.6.4 自检脚本片段（Claude 跑完整 grep 命令做尽职检查）

```bash
# 1. 总数
jq '.sources | length' raw/sources.json   # 应 ≥ 15

# 2. 等级分布（S/A/B/C 四档）
jq '[.sources[].grade] | group_by(.) | map({grade: .[0], count: length})' raw/sources.json
# 必须满足：S ≥ 2、A ≥ 2、B ≥ 3、C 不限

# 3. S 级中至少 1 条中国境内官方
jq '[.sources[] | select(.grade=="S" and .country=="CN")] | length' raw/sources.json   # 应 ≥ 1

# 4. 双源率
grep -c '| ✅ |' raw/data_index.md
grep -c '| ⚠️ |' raw/data_index.md
# 双源率 = ✅ / (✅ + ⚠️)，需 ≥ 60%

# 5. material 文件齐全性
jq -r '.sources[].file' raw/sources.json | while read f; do test -f "raw/$f" || echo "missing: $f"; done

# 6. 数据缺口非空
grep -A 100 '## 数据缺口' raw/index.md | grep -c '^- '   # 应 ≥ 1
```

### §2.7 失败处理与重试

§2 全程会撞到三类失败：单条 URL 抓不到、WebSearch 整体不出结果、整类来源严重不足。三类处理方式不一样，**不要一刀切重试**。

#### §2.7.1 单条 WebFetch 失败（403 / 404 / 超时 / 空内容）

- **不重试相同 URL**：重试只会浪费 token，且对方很可能继续封
- 在 `raw/sources.json` 追加一条记录，`status: fetch_failed`、`note` 写失败原因（HTTP 状态码 / 超时 / 内容为空）；**不**为该来源建 material 文件
- 找替代关键词或备用站点（**只能在 §2.2 白名单内换**，不许临时引入新站）：
  - 同一指标换一家机构：信通院拿不到 → 试国家统计局相邻类目 / 巨潮上市公司年报相邻表
  - 同一新闻换一家媒体：36 氪正文为空 → 试界面新闻 / 第一财经
  - 同一主题换关键词："2024 家用咖啡机销量"拿不到 → 改"家用咖啡机零售额 2024" / "咖啡电器 销售数据"
- 同一指标三家替代源都失败 → 进入 §2.7.3 的"整类不足"路径

#### §2.7.2 WebSearch 整体返回空 / 国内代理不稳

WebSearch 返回 0 条或全部是无关结果时，按下面顺序兜底：

1. **换搜索词的描述方式**：「市场规模」→「市场容量」/「行业规模」；「头部玩家」→「TOP10」/「龙头企业」
2. **加时间限定**：在 query 里加上具体年份（2023 / 2024），避免命中过时旧文
3. **走站内搜索 URL fallback**：直接对单站构造 URL，跳过 WebSearch
   - 36 氪：`https://36kr.com/search/articles/<keyword>`
   - 界面新闻：`https://www.jiemian.com/search.html?keyword=<keyword>`
   - 第一财经：`https://www.yicai.com/search?keys=<keyword>`
   - 国家统计局：`http://search.stats.gov.cn/search?query=<keyword>`
   - 京东搜索：`https://search.jd.com/Search?keyword=<keyword>`
   - 维基百科：`https://zh.wikipedia.org/wiki/Special:Search?search=<keyword>`
4. **降低搜索深度，提升广度**：把"前 10 条精挑"改成"前 30 条粗筛后人工挑 5 条"
5. 上述全部尝试后仍然 0 结果 → 在 `raw/index.md` 数据缺口章节明示"该关键词在公开搜索引擎下无可用一手来源"

#### §2.7.3 一类来源严重不足时的硬停机制

如果完成 §2.6.1 数量门槛检查时发现**某一类来源严重不足**（**S 级 < 2** 且无中国境内官方 / **A 级 < 2** / 头部玩家 < 3 个），**立即停下来**，不要硬上回报完成。

停下时给用户的同步必须包含：

```
赛道 <track_keyword> 公开渠道采集已完成，但 <某类> 来源严重不足，原因：
1. <具体说明>
2. <具体说明>

继续做分析的风险：
- <说明会导致报告里哪些章节失真>

建议三选一：
A. 你确认放弃 <某章节>，我跳过该章节继续分析（报告里会明示数据缺口）
B. 你提供 <数据/文档> 后我重新进入采集
C. 终止本次跑批，建议人工补采或换其它渠道

请回复 A / B / C。
```

不允许"我先按 A 跑了再说"的自主决断——分析阶段一旦开跑就是不可回退的，必须先拿到用户确认。

**自检**：你现在停下来是因为客观数据不足、还是因为搜索次数没用够？如果是后者，先补搜再判断。
