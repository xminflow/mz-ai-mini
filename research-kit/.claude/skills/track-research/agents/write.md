# track-research · 创作 agent 执行指南

本文件由 track-research 主 SKILL.md 通过 Agent 工具调用 general-purpose 子 agent 时附在 prompt 里使用。子 agent 启动后第一件事就是 Read 本文件，按此执行。

本指南专注于赛道分析的「创作」环节——在采集 agent 已经把底稿（`sources.json` / `data_index.md` / `index.md` / `material/*.md`）准备好的前提下，由本 agent 把这些底稿拆解、提炼、组织成 6 份生产级 HTML 报告。本 agent 不负责数据采集，也不负责后置内容审核。

## 接口契约

- **输入**：主 SKILL 会传入下列参数（全部为必需）。
  - `track_keyword`：原始赛道关键词（如"家用咖啡机评测"）
  - `region`：地域（如"中国大陆"）
  - `audience`：读者画像（如"准备进场的独立创业者"）
  - `track_slug`：拼音连字符 slug（如 `jiayong-kafeiji-pingce`）
  - `run_id`：本次运行的唯一标识
  - `workspace_dir`：本次运行的工作目录绝对路径
  - `raw_dir`：底稿目录绝对路径（已由采集 agent 填齐 `sources.json` / `data_index.md` / `index.md` / `material/*.md`）
  - `reports_dir`：本 agent 的 HTML 输出目录绝对路径

- **输出**：在 `<reports_dir>/` 下产出 6 份 HTML + 1 份 index.json，仅此而已：
  - `00_overview.html`
  - `01_market.html`
  - `02_competition.html`
  - `03_business_model.html`
  - `04_ai_driven_analysis.html`
  - `05_playbook.html`
  - `index.json`
  - **不再生成** `<raw_dir>/charts/*.png` / `<raw_dir>/charts_manifest.json`——所有数据图全部内联到 HTML（详见本文件 §6）

- **index.json 必填字段**（发布层强制校验，缺任何一个或字段名错误都会导致 `publish-track` 失败）：

  | 字段 | 类型 | 来源 | 备注 |
  |---|---|---|---|
  | `run_id` | string | 上下文变量 | 直接取 |
  | `track_keyword` | string | 上下文变量 | 原始关键词 |
  | `track_slug` | string | 上下文变量 | 拼音连字符 |
  | `region` | string | 上下文变量 | 如 `中国大陆` |
  | `audience` | string | 上下文变量 | 如 `个人创业者` |
  | `generated_at` | string | 当前 UTC | ISO 8601，如 `2026-05-21T08:00:00Z` |
  | `stance` | string | `00_overview.html` 一句话判断 | 枚举：`看好` / `谨慎看好` / `谨慎` / `看空` |
  | `stance_summary` | string | `00_overview.html` hero 区 | ≤ 50 字，解释立场核心逻辑 |
  | `key_numbers` | object | `raw/data_index.md` | 至少 6 个量化指标；**键名必须从下文「§0 key_numbers 标准字段白名单」中选取**，自造键名会在官网卡片上裸奔成英文（已多次出过事故，禁止重蹈）|
  | `data_sources_count` | int | `raw/sources.json` → `total` 字段 | 直接取整数 |
  | `reports[].type` | string | 固定枚举 | **必须**是以下之一：`overview` / `market` / `competition` / `business_model` / `ai_analysis` / `playbook`；**禁止**用 `id` / `00_overview` 等其他形式 |
  | `reports[].file` | string | 固定文件名 | 如 `00_overview.html`；**禁止**用 `path` / `filename` 等其他字段名 |
  | `reports[].title` | string | 各 HTML `<title>` 中的短标题 | |
  | `reports[].sections` | int | 各 HTML 实际章节数 | 写完 HTML 后填写真实值 |
  | `reports[].charts` | int | 各 HTML 实际图表数 | 含 SVG + CSS 横条 |
  | `reports[].description` | string | 各 HTML 内容 | ≤ 60 字 |

  写完 6 份 HTML 后再写 `index.json`（`stance` / `stance_summary` 需从 `00_overview.html` 提取，`sections` / `charts` 需从各 HTML 统计实际值）。

- **完成回报格式**：完成后用一段简短中文回报给主 SKILL，包含：
  - 6 份 HTML 的绝对路径
  - 每份 HTML 的章节自检 grep 命令命中数（禁用术语 / 来源脚注 / 跨页跳转 / 数据图数量）
  - **不要回报完整的 HTML 内容**

## §0 `key_numbers` 标准字段白名单（**写 index.json 前必读**）

### §0.1 为什么有白名单

`index.json.key_numbers` 不是给你自己看的——它直接喂给官网赛道卡片做"三个亮点数字"展示。官网卡片只识别下表列出的标准键名：命中标准键名 → 显示中文 label + 单位；命中非标准键名 → **裸奔显示原始英文 key**（如 `female_user_pct 77.5`）。

历史上每次新赛道（尤其是内容 / 情绪 / 心理类）都因为"按数据感觉造键名"翻车（`top_kol_followers_peak`、`female_user_pct`、`xuanxue_consumption_sam_cny_100m` 等），玄学经济赛道是最近一次复发。本节即根治该问题。

### §0.2 白名单标准字段表

| 标准字段名 | 含义 | 单位 | 卡片优先级 |
|---|---|---|---|
| `som_cny_100m` | 可获市场 SOM | 亿元 | ⭐ 最优先 |
| `market_size_cny_100m` | 当前年市场规模 | 亿元 | ⭐ 次优先 |
| `sam_cny_100m` | 服务可及市场 SAM | 亿元 | — |
| `market_size_2024_cny_100m` | 2024 市场规模 | 亿元 | — |
| `market_size_2025_cny_100m` | 2025 市场规模 | 亿元 | — |
| `market_size_2026e_cny_100m` | 2026E 市场规模（预测）| 亿元 | — |
| `market_size_2030e_cny_100m` | 2030E 市场规模（预测）| 亿元 | — |
| `cagr_forecast_pct` | 预测 CAGR | % | ⭐ 优先 |
| `cagr_historical_pct` | 历史 CAGR | % | — |
| `cr5_pct` | CR5 集中度 | % | ⭐ 优先 |
| `cr10_pct` | CR10 集中度 | % | — |
| `ecommerce_penetration_pct` | 电商渗透率 | % | ⭐ 优先 |
| `startup_cost_base_cny` | 启动成本（中性）| 元 | ⭐ 优先 |
| `startup_cost_conservative_cny` | 启动成本（保守）| 元 | — |
| `startup_cost_optimistic_cny` | 启动成本（乐观）| 元 | — |
| `hit_rate_pct` | 中签率（内容赛道）| % | — |
| `avg_roi` | 平均 ROI | × | — |
| `traffic_cost_share_pct` | 流量成本占比 | % | — |
| `production_cost_per_min_cny_2025` | 单分钟成本（内容赛道）| 元 | — |
| `individual_tool_cost_per_month_cny` | 个人月工具成本 | 元 | — |

官网卡片按下列顺序挑前 3 个填槽（命中即取）：

```
som_cny_100m → market_size_cny_100m → cagr_forecast_pct → cr5_pct
→ ecommerce_penetration_pct → startup_cost_base_cny
→ market_size_2025_cny_100m → hit_rate_pct → avg_roi
→ traffic_cost_share_pct → market_size_2030e_cny_100m
```

### §0.3 硬约束

1. **必须至少包含 4 个白名单字段**（卡片最多展示 3 个，留 1 个冗余防止其中某个被审查删掉）。
2. **强烈推荐 4 个"通用兜底组合"全部齐备**：`market_size_cny_100m` + `cagr_forecast_pct` + `cr5_pct`（数据不可得时填 `startup_cost_base_cny` 顶替）+ `som_cny_100m`。即便数据公开渠道仅有粗略量级，也用机构估算填——填了能展示中文，留空就会被非白名单字段顶上来裸奔。
3. **非白名单字段允许补充**（自媒体类赛道常见的女性占比、头部 KOL 粉丝峰值、客单价区间等），但**必须使用纯中文键名**（如 `女性用户占比_pct`、`头部KOL粉丝峰值_万`），不允许英文 + 下划线的形态。中文键名命中卡片 fallback 时至少裸奔成中文标签，不会暴露工程痕迹。
4. **任何键名缺单位后缀都视为硬错误**——`_cny_100m`（亿元）/ `_cny`（元）/ `_pct`（百分比）/ `_万`（万）/ `_x`（倍数）五选一，按 §0.2 表对齐。
5. **写完 `index.json` 后用以下 grep 自检**（命中数应 = 0）：

   ```bash
   grep -oE '"[a-z][a-z_0-9]*":' \
     output/tracks/<track_slug>/reports/<run_id>/index.json \
     | sort -u
   ```

   把输出列表逐项与 §0.2 白名单对照；任何"看起来像英文工程命名但不在白名单"的键名一律改写为白名单标准键或纯中文键。

### §0.4 数据缺口处理

某个白名单字段公开渠道完全找不到时（如冷门赛道无机构 CAGR），允许：

- 用相邻指标外推（如已知 2022 / 2024 两点 → 算 2 年 CAGR 填入 `cagr_historical_pct`）
- 用 3-5 家可比赛道的均值打分（在 `data_index.md` 注明出处）
- **不允许** 直接省略该字段、然后用非白名单字段凑数

如果实在补不齐 4 个白名单字段（极小众赛道），在主 SKILL 完成回报中明示"key_numbers 仅含 N 个白名单字段，卡片可能展示非白名单字段"，由主会话决定是否回流重采。

## §1 读法

按序读底稿：

1. `raw/sources.json` —— 拿到来源全貌（站点 / 等级 / 时间）
2. `raw/data_index.md` —— **唯一权威数据源**，所有报告里的数字必须能反查到这里
3. `raw/index.md` —— 拿到 5 维度关键词矩阵 + 数据缺口
4. `raw/material/*.md` —— 拿到原文细节、定性判断、案例故事

读法约束：

- 先通读一遍 `data_index.md` 的 4 张表，**禁止跳过表头看表身**——表头里写了等级、双源验证状态、时效窗，这些是后续判定"事实 / 预测"的关键
- 把 4 张表的关键数字（市场规模、增速、Top 5 玩家粉丝/营收量级、客单价、利润率）抄到一张草稿上，作为整个创作环节的"工作内存"，写每章前先核对
- `material/*.md` 不通读，按需检索：写到哪一节、检索哪几条 material；读完后在草稿上记"本节引用的 material id 列表"

**禁止**：

- 从未在 `data_index.md` 出现过的来源里取数字写入报告
- 引用某个数字时直接抄 material 原文行，不回 `data_index.md` 校对单位/年份/双源状态
- 把 `index.md` 的"数据缺口"章节当成可以"凭印象补满"的清单

**自检**：开始写第一份 HTML 之前，你必须能口头复述 `data_index.md` 4 张表里的关键数字——市场规模、CAGR、Top 5 玩家名字、客单价区间。复述不出来就回读底稿，不要硬写。

## §2 写作顺序与依赖

```
01_market  ─┐
            ├──→ 03_business_model ──→ 04_ai_driven_analysis ──→ 05_playbook ──→ 00_overview
02_competition ─┘
```

固定顺序（不可乱）：

| # | HTML | 何时写 | 依赖什么 |
|---|---|---|---|
| 1 | `01_market.html` | 第 1 个写 | 仅依赖底稿（无前置 HTML）|
| 2 | `02_competition.html` | 第 2 个写（与 01 并行也可） | 仅依赖底稿 |
| 3 | `03_business_model.html` | 第 3 个写 | 依赖 01 的"用户分析"章节、02 的"竞争矩阵 / 差异化空间" |
| 4 | `04_ai_driven_analysis.html` | 第 4 个写 | 依赖 03 的"价值链 / 成本结构"，AI 落地点正是从成本结构倒推出来 |
| 5 | `05_playbook.html` | 第 5 个写 | 依赖 01 / 02 / 03 全部；财务三场景需要 01 的市场规模 + 02 的客单价 + 03 的成本结构 |
| 6 | `00_overview.html` | **最后写** | 依赖前 5 份全部，**只提取最锋利论点，禁止引入新数据** |

两条排序原则：① `00_overview` 必须最后写（先 5 份长文再压摘要，否则会"自我命题"倒推证据）；② `01_market` 与 `02_competition` 独立（市场盘子与竞争格局两条研究线不能互相喂答案）。

**自检**：写到 `03_business_model.html` 时，桌面上必须开着 `01_market.html` 和 `02_competition.html`，且能指出 03 的"目标客户"章节引用的是 01 的哪一节、03 的"竞争与护城河"章节引用的是 02 的哪一节。指不出来 = 03 没写好，回去补。

## §3 6 份 HTML 详细写作指引

每份 HTML 必须从对应的 `templates/<name>.html.tmpl` 派生。本节为每份 HTML 写一节，逐章给出"该写什么 / 必须答的问题 / 推荐 HTML 结构 / 独有判断框架"。

写每章时先看本节对应小节，再看模板里章节内的二级 TODO 注释（模板 TODO 只是"在该位置就近提醒"，本节才是首要权威）。两者冲突以本节为准。

### §3.1 `00_overview.html` — 引流型摘要

- **用途定位**：30 秒说清核心矛盾 + 机会窗口 + 谁该做谁不该做。**本份必须独立完整**——不依赖、不跳转到其他 5 份 HTML。
- **读者画像**：拿到报告 30 秒内决定要不要继续看的人（投资人 / 业务负责人 / 准入局者）
- **写作语气**：投资备忘录，干脆利落；句子短、动词强、判断词不含糊（看好 / 谨慎 / 看空 三选一明确表态）
- **章节骨架**（8 章；不再有"六份 HTML 导航"章节）：

  | # | 锚点 ID | 标题 | 关键判断（2-3 条）|
  |---|---|---|---|
  | 1 | `timestamp` | 数据时效声明 | 主要数据截止年份 / 数据缺口透明披露 / 证据等级总判定 |
  | 2 | `hero` | 标题 + 钩子 + 一句话判断 + **市场规模数据图** | 标题含锋利判断或反差数字 / 钩子用反常识或强对比 / 一句话判断 ≤ 30 字含明确表态 / **顶部用一张内联 SVG 柱状/折线图展示市场规模 3 年走势 + CAGR**（取代旧装饰封面）|
  | 3 | `three-numbers` | 三个关键数字 | 三个数字必须是事实类（**禁止预测**）/ 优先选打破直觉的数字；若赛道数字均符合直觉，则选"头部集中度 / 增速反转 / 规模量级"中最有决策价值的三个 |
  | 4 | `why-now` | 为什么是现在 | 3 条窗口期分析 / 每条带具体时间锚点（如"2024 Q3 出台 XX 政策"）/ 给出窗口剩余时长 |
  | 5 | `verdicts` | 关键结论（3-5 条）| 每条 = 立场标签（看好/谨慎/看空）+ 一句话结论 + 一句证据 |
  | 6 | `audience` | 适合谁做 | ✅/⚠️/❌ 三栏（适合 / 慎入 / 不适合）/ 每栏 3-5 条具体画像 / 每条要"角色 + 资源 + 心力门槛"。模板已硬编码三栏 emoji + 配色 `#34d399 / #fbbf24 / #f87171`，请按模板填内容、不要替换 emoji |
  | 7 | `answers` | 这份报告能帮你回答什么 | 5-8 条具体问题，**纯文字 / 普通 `<li>`，不挂跳转**（每份 HTML 独立完整）/ 也列出**不能**回答的问题 |
  | 8 | `guide` | 阅读指南 | 30 秒 / 5 分钟 / 30 分钟 / 1 小时 四档读者推荐路径，**纯文字描述各档读什么内容，不挂跳转链接** |

- **必答问题**：无（引流型，不放 qa-card）
- **硬底线**（写完逐条勾选）：
  1. **hero 区市场规模数据图**：内联 SVG，含坐标轴 + 网格 + 数据标签 + 预测段虚线，每个数据点都能在 `data_index.md` 找到
  2. hero 一句话判断 ≤ 30 字、必须含 "看好 / 谨慎 / 看空" 中一个明确表态
  3. three-numbers 三个关键数字必须是事实类，**禁止预测数字**；优先反常识，无反常识数字时选"最具决策价值"的三个
  4. why-now 三条窗口期分析每条必须给具体时间锚点
  5. verdicts 3-5 条，每条都是"判断 + 一句证据"
  6. **本份不出现任何 `<a href="0X_xxx.html">` 跨页跳转**——`answers` 与 `guide` 节用纯文字描述各份内容
  7. **本份不出现"六份 HTML 导航"或类似 Continue Reading footer**
  8. **本份不出现装饰性 SVG 封面**——顶部只允许"承载数据的图表"
- **推荐 HTML 结构**：
  - hero 区 → `<h1>` 标题 + 一句话判断 `<span class="text-shimmer">` + 一张内联 SVG 数据图 `<svg viewBox="0 0 800 360">`（柱状或折线）+ `<figcaption>` 数据来源
  - 三个关键数字 → 三栏 grid，**每栏必须用 `.stat-callout` 三行结构**（大数字 / 来源小字行 / 解释段落），不要把脚注塞进大字行里。模板示例（已在每份 HTML 的 `<head>` 注入对应 CSS）：

    ```html
    <dl class="grid grid-cols-1 sm:grid-cols-3 gap-6 border-y border-white/10 py-7">
      <div class="stat-callout">
        <dt class="stat-value">80%</dt>
        <p class="stat-source">来源：<a href="URL" target="_blank">新浪财经</a>，2026</p>
        <dd class="text-[14px] leading-[1.75] text-ink-soft">作品播放量 &lt; 100 万，无法变现……</dd>
      </div>
      <!-- 第 2、3 个关键数字结构相同 -->
    </dl>
    ```

    **硬底线**：
    - **禁止**把 `<span class="citation">` 嵌入 `.stat-value`（或任何 `text-4xl`/`text-5xl` 父元素）里——脚注会继承大字号被撑成 36px 视觉灾难
    - 段落正文中的来源脚注用 `<span class="citation">（来源：<a href="URL" target="_blank">机构</a>，年份）</span>`，CSS 已强制小字、浅灰、整体不换行
  - 窗口期 / 适合谁做 → `<div class="judge-card">` + `<div class="label">` 头部
  - 关键结论 → `<table class="report-table">` 三列：立场 / 结论 / 证据要点
- **独有判断框架**：无新框架，只做"提炼 + 排序"——把后 5 份 HTML 的每一份最锋利的 1 条判断挑出来，按"震撼度"排序

**自检**：写完 `00_overview.html` 后做一次"删行测试"——删掉本份任何 1 节，读者还能 30 秒决策吗？不能 = 那节是核心，留；还能 = 那节是冗余，删。再做一次"grep 测试"：搜 `href="0[0-5]_` 命中数必须为 0。

### §3.2 `01_market.html` — 行业研判

  | # | 锚点 ID | 标题 | 关键判断 |
  |---|---|---|---|
  | 1 | `fit-check` | 你适合做这个吗 | 决策清单 + 决策树 + 止损标准 |
  | 2 | `failures` | 常见失败模式（**≥ 3 种**）| 每种 = 模式名 + 根本原因 + 真实案例 + 早期信号 |
  | 3 | `zero-to-one` | 从零到一启动指南 | 4 阶段（第 1-4 周 / 第 5-8 周 / 第 9-12 周 / 第 13-26 周），**周级颗粒度** |
  | 4 | `monetize-how` | 怎么赚钱 | 每种收入来源结构化：触发条件 / 客单价 / 转化率 / 现金流时序 |
  | 5 | `monetize-how-much` | 能赚多少 | 启动成本 + 1/3/6/12 月爬坡 + **三场景（保守 / 中性 / 乐观）** + 敏感性分析 |
  | 6 | `resources` | 行业资源导航 | 工具 / 社群 / 课程 / 服务商，每条带公开来源 |

- **failures 每种失败模式必写 4 项**：
  - **模式名**：一句话起名（如"前期狂砸 SEM、零自然流量积累"）
  - **根本原因**：失败的结构性原因（不是表面现象）
  - **真实案例**：至少 1 个公开案例（带 material 来源）
  - **早期信号**：3 个月内能察觉的早期警告

- **zero-to-one 4 阶段每阶段必写**：
  - 本阶段目标（一句话，数字化）
  - 本阶段产出物（具体可见的东西）
  - 本阶段周计划（按周列任务）
  - 本阶段烧钱预算（精确到月）
  - 本阶段止损线（满足什么条件应该撤退）

- **monetize-how-much 三场景模板**：
  - 保守场景：客单价 × 转化率 × 月流量 都取下界
  - 中性场景：取中位数
  - 乐观场景：取上界（但不能脱离 02 头部玩家的天花板）
  - 每个数字必须标计算依据（如"客单价 199 元 = data_index.md 表 3 行 5 的中位数"）
  - 敏感性分析至少 2 个变量（如"客单价变化 ±20% 对净利的影响 / 月流量变化 ±30% 对净利的影响"）

- **必答问题**（每章 5 个）：
  - **fit-check**：① 三个最关键的"适合"特征？② 三个最关键的"不适合"特征？③ 决策树的根节点问题？④ 止损线设在哪？⑤ 自我评估打分表怎么用？
  - **failures**：① 最高发的失败模式？② 最致命的失败模式（一次就死）？③ 早期信号最隐蔽的一种？④ 失败案例的公开来源？⑤ 如何主动规避？
  - **zero-to-one**：① 第 1-4 周最关键的产出物？② 第 5-8 周的拐点动作？③ 第 9-12 周的爬坡指标？④ 第 13-26 周的扩张时机？⑤ 每个阶段的烧钱上限？
  - **monetize-how**：① 主要收入来源？② 副业收入来源？③ 收入的现金流时序（提前 / 即时 / 滞后）？④ 哪种收入最稳定？⑤ 哪种收入有最大杠杆？
  - **monetize-how-much**：① 启动成本量级（人民币）？② 6 个月预计净利？③ 三场景的差距？④ 敏感性最高的变量是？⑤ 多久能回本？

- **推荐 HTML 结构**：
  - 决策树 → 内联 SVG（节点 + 分支）或 `<details>` 嵌套
  - 失败模式 → 每种一个 `<div class="judge-card">` 红色标签 + 4 项 `<h4 class="subhead">`
  - 4 阶段 → 4 个 `<section>` 子块，每个内含周表 `<table class="report-table">`
  - 三场景财务预测 → `<table class="report-table">` 三列对照 + 1 张折线图（预测段虚线）
  - 行业资源导航 → `<ul>` 分类列表
  - 必答问题 → 每章末 `<div class="qa-card">`

- **独有判断框架**：
  - **fit-check 三维**：① 资源匹配（资金 / 时间 / 技能 / 关系）② 心力匹配（能扛多久零回报）③ 时机匹配（错过窗口的代价）
  - **失败模式分类**：方向错（赛道选错）/ 节奏错（时间分配错）/ 资源错（钱花错地方）/ 心态错（情绪化决策）
  - **财务三场景**：保守 / 中性 / 乐观，每个数字带计算依据；敏感性分析变量 ≥ 2 个；预测段在图表中必须虚线 + 浅色 + "E" 标识

- **必备图**：见 §6.4 表

**自检**：monetize-how-much 三场景表里的每个数字，能不能在表格旁边或下方用一行注释说清"= XX × YY"？不能 = 数字凭空冒出，立即补依据或删除。

## §4 防幻觉四分类

每章写完后逐句自检，每个陈述必须能归到下面四类之一：

| 类别 | 标识 | 验证标准 |
|---|---|---|
| **事实** | 必须有脚注 `（来源：[机构](URL)，年份）` | 在 `data_index.md` 能找到对应行，数字精度与单位与来源完全一致 |
| **分析** | 用「综合来看」「由此判断」「这意味着」等分析性语态 | 可顺藤摸瓜追溯到 1-2 条事实 |
| **建议** | 显式 What / Why / How 三段式 | What 是动作，Why 引一条事实，How 是具体步骤 |
| **预测** | 标"预测"或"E"或带虚线视觉 | 标注计算公式与假设；提供保守/中性/乐观三场景；与事实视觉区分 |

**写完每章后强制自检**（用一张草稿表）：

1. 列出该章所有出现的数字（grep `[0-9]+(亿|万|%|元|条|个|家|x|倍)` 即可）
2. 逐一标 `fact` / `analysis` / `recommendation` / `projection` 类别
3. 不归入任何类别的数字立即删除
4. `fact` 类必须有脚注；`projection` 类必须标注假设公式；`analysis` 类必须能追溯到 1-2 条 `fact`；`recommendation` 类必须含 What/Why/How
5. 财务预测必须**三场景**（保守 / 中性 / 乐观）——单一预测数字一律不允许出现

**禁止**：
- 没有归类的"看起来像分析"的句子
- 事实 + 预测混着写，让读者分不清哪些是真发生的、哪些是推测的
- 把建议写成"应该""可以"开头的虚词，没有可操作的具体步骤
- 用"约 X" / "大约 X" / "X 左右"模糊化数字——要么给精确值 + 来源，要么改为定性描述

**自检**：完成本章后，把上面那张草稿表贴在该章开头作为"内部脚手架"（写完最终稿前会被删掉，但写作过程中必须存在）。

## §5 正文专业自信原则

正文是给读者看的成品文本，**所有暴露"我们怎么拿到这些数据 / 数据有多弱 / 内部审查痕迹 / 工程实现"的词汇都必须改写或删除**；同时**所有夸大、迎合、把推测包装成事实的措辞也必须删改**——专业不等于乐观，看好 / 谨慎 / 看空必须由证据决定，不能由"想让用户高兴"决定。

写完报告 Ctrl+F 搜下表每一项，命中即必修：

| 类别 | 禁用词（命中即违规） | 改写策略 |
|---|---|---|
| **来源等级** | `A 级一手`、`B 级转引`、`S 级`、`一手来源`、`二手转引` | 删除或换成"机构名 + 年份" |
| **置信度** | `置信度：高/中/低`、`（置信度：中等）`、`高置信度`、`低置信度` | 删除——置信度由叙述方式体现，不要写成元数据 |
| **数据获取状态** | `原报告未取得`、`PDF 未下载`、`白皮书未`、`未获取`、`抓取失败` | 删除或改"公开渠道不可得，本报告不提供" |
| **来源强度自述** | `未交叉验证`、`非独立验证`、`服务商自述`、`据 XX 转引`、`来源较弱` | 删除或含蓄限定，例如"根据机构 X 的口径" |
| **夸大词** | `百分百`、`绝对`、`必然`、`稳赚`、`躺赢`、`无脑做`、`爆款`、`蓝海`、`风口已至`、`下一个万亿`、`颠覆性`、`革命性`、`完美`、`无懈可击` | 删除或改用具体数字与时间窗（如"6-12 个月内 ROI 1.2-1.5 倍"）|
| **迎合词** | `非常适合`、`强烈推荐`、`千万不要错过`、`抓住机会`、`遥遥领先`、`必将`、`一定会`、`所有人都能` | 删除——立场只能是 看好 / 谨慎 / 看空 三档，且必须配 2-3 条证据 |
| **以偏概全** | `头部账号都能 XX`、`只要 XX 就能 XX`、`所有创业者`、`普通人也能轻松` | 改写为具体条件，如"满足 X / Y / Z 三条的团队，6 个月内可达 XX" |

| **审查痕迹** | `数据缺口`、`待补充`、`需后续核验`、`本节存在 X 问题` | 删除——审查信息只出现在 `check_report.md`，不在 6 份 HTML 里 |
| **工程术语** | `WebSearch`、`WebFetch`、`抓取`、`登录墙`、`material 目录`、`data_index`、`sources.json`、`research-kit`、`track_slug`、`track-research`、`run_id`、`raw/`、`workspace` | 完全不出现 |
| **完工/进度类** | `完成进度`、`分析进度`、`任务进度`、`采集进度`、`生成完毕`、`本报告已完成`、`审查轮次`、`final_status`、`check_report`、`硬错误`、`6 份 HTML 全部生成`、`已交付`、`报告交付`、`v0.X.0` | 完全不出现——这些是工程进度，与读者无关；HTML 末尾**不**写"完成进度"章节，**不**写"报告交付"卡片 |
| **跨页跳转** | `<a href="00_overview.html">`、`<a href="01_market.html">` ... `<a href="05_playbook.html">`（任何对其他 5 份 HTML 的 a 标签跳转） | 6 份 HTML 之间**禁止互相跳转**——每份必须独立完整。页内 anchor 跳转（如 `<a href="#top-players">`）允许 |

## §6 数据可视化纪律

**总原则：重点数据必须用直观图展示，禁止依赖 highcharts MCP 或任何外部图表服务。所有图表统一为内联 SVG + CSS 横条两种实现路径。**

### §6.1 禁止项（红线）

- **禁止装饰性 SVG 封面 / hero 插画**：不再有"viewBox 1600×900 + 渐变背景 + 几何 + 数据 callout 卡"的封面 SVG。任何 SVG 都必须承载**真实可读的数据信息**（条/柱/饼/折线/矩阵点），不允许"纯装饰 + 文字嵌入"
- **禁止调用 `highcharts_chart_image` MCP**：环境中即使存在该工具也不调用；不再产生 `data-rk-chart` 占位符；不再生成 `<raw_dir>/charts/*.png`；不再生成 `<raw_dir>/charts_manifest.json`
- **禁止外链图片**：所有 `<img>` 的 `src` 必须为 `data:image/...;base64,...`；HTTP / HTTPS 外链图片一律不准出现
- **禁止"光秃秃的表格 + 大数字"组合**：每份 HTML 的"重点数据章节"必须至少 1 张直观图（详见 §6.4 每份 HTML 必备图清单）

### §6.2 可视化形态选择

按数据类型选用对应形态，不要混用：

| 数据类型 | 推荐形态 | 实现方式 |
|---|---|---|
| 单一变量时间序列（如市场规模 2019-2030E） | 柱状图 / 折线图 | 内联 SVG `<svg viewBox="0 0 800 360">` |
| 多变量对比（如三场景财务预测） | 多色折线 + 预测段虚线 | 内联 SVG `<svg viewBox="0 0 800 360">` |
| 结构占比（如收入构成、成本拆解） | 横条百分比 / 环形图 | CSS Grid + `<div style="width:X%">` 横条，或内联 SVG 环形 |
| 等级评分（如玩家能力对比） | 雷达图 / 评分卡 | 内联 SVG `<svg viewBox="0 0 600 600">` |
| 二维分布（如定位矩阵 X×Y） | 散点矩阵 | 内联 SVG `<svg viewBox="0 0 800 600">` |
| 流程链路（如 AI 介入价值链） | 节点图 | 内联 SVG `<svg viewBox="0 0 1000 400">` |

横条 / 进度条优先用 CSS（更轻、更易读），柱状 / 折线 / 饼 / 矩阵 / 流程必须用内联 SVG。

### §6.3 内联 SVG 视觉硬要求

每张内联 SVG **必须**包含下列元素，任一缺失即硬错误：

- `viewBox` 属性必填
- 坐标轴 + 网格线 + 轴标签 + 单位
- 数据标签（每个柱/点旁边的数字标注），不允许"读者要用眼估读"
- 图例（多色情况）
- **预测段视觉区分**：虚线 (`stroke-dasharray="6,4"`) + 浅色 (`opacity="0.55"`) + "E" 或"预测"文字标注
- 事实 / 预测分界处必须有竖向辅助线 + 文字标签（如"2025"）
- 配色与全文一致：主色 `#10b981`（report 绿）/ 辅色 `#A78BFA`（accent 紫）/ 中性灰 `#8A8A94` / 文字 `#F5F5F7`
- 图外必须有 `<figcaption>`，格式：`图 N · <标题> · 数据来源：<机构A> / <机构B>，<年份>`

CSS 横条结构（百分比 / 评分类）参考片段：

```html
<div class="space-y-3 my-6">
  <div>
    <div class="flex justify-between text-[13px] mb-1.5">
      <span class="text-ink-soft">B 端定制收入</span>
      <span class="font-mono text-report">42%</span>
    </div>
    <div class="h-2 bg-white/[0.06] rounded-full overflow-hidden">
      <div class="h-full bg-report rounded-full" style="width:42%"></div>
    </div>
  </div>
  <!-- 继续 N 行 -->
</div>
```

### §6.4 每份 HTML 必备图清单

## §7 章节自检 grep 清单

每份 HTML 写完后，用下列 grep 命令验证（Bash 工具执行；把 `<run_id>` 与 `<track_slug>` 替换为实际值）：

```bash
# 1. 工程 / 自我打折 / 完工进度 禁用术语命中应为 0
grep -E "(A 级|B 级|S 级|置信度|未获取|未交叉验证|据相关数据|待补充|数据缺口|完成进度|分析进度|生成完毕|本报告已完成|审查轮次|final_status|check_report|硬错误|报告交付|WebSearch|WebFetch|抓取|material|data_index|sources\.json|run_id|track_slug|track-research|highcharts|data-rk-chart)" \
  output/tracks/<track_slug>/reports/<run_id>/*.html

# 2. 跨页跳转命中应为 0（每份 HTML 必须独立完整）
grep -E 'href="(00_overview|01_market|02_competition|03_business_model|04_ai_driven_analysis|05_playbook)\.html' \
  output/tracks/<track_slug>/reports/<run_id>/*.html

# 3. 含蓄限定可接受，但应少于 5 处
grep -E '据[^（]*报告[^，。]*$' output/tracks/<track_slug>/reports/<run_id>/*.html

# 4. 每份 HTML 至少出现 5 次"（来源：" 脚注
grep -c '（来源：' output/tracks/<track_slug>/reports/<run_id>/*.html

# 5. 每份 HTML 至少出现 N 张数据图（内联 <svg viewBox 或 CSS 横条容器）
grep -cE '<svg [^>]*viewBox|<div class="h-2 bg-white' output/tracks/<track_slug>/reports/<run_id>/*.html
```

通过条件：

- 命令 1 → 命中数 = **0**（任何命中都是硬错误）
- 命令 2 → 命中数 = **0**（每份 HTML 必须独立完整，禁止跨页跳转）
- 命令 3 → 命中数 < **5**（含蓄限定语适度可接受，过多说明全篇靠"据 XX 报告"撑场）
- 命令 4 → 每份 HTML 命中数 ≥ **5**（说明数字脚注密度足够）
- 命令 5 → 每份 HTML 命中数 ≥ §6.4 表中该 HTML 的"至少"列（如 `01_market.html` ≥ 2）

任一条不通过 = 回到对应小节修改，**不**交付。

**自检**：5 条命令全部跑过一遍，把命中数贴在工作日志里作为完工标记，并在向主 SKILL 的回报中包含这些命中数。

## 附录 · 写作硬约束汇总

### 数字与引用

- 每个数字后必须有脚注 `（来源：[机构](URL)，年份）`
- 每个数字必须能在 `raw/data_index.md` 找到对应行
- 同一数字在不同 HTML 必须一致（精度、单位、年份都一致）
- 引用 URL 必须能在 `raw/sources.json` 找到，不允许伪造
- 数字缺口处用"公开渠道不可得，本报告不提供"明示，**不编造**

### 禁用术语

权威清单见 §5 表 + §7 grep 命令，本附录不重复。

### HTML 卫生

- `<html lang="zh-CN">`
- Tailwind CDN 已注入 `<head>`：`<script src="https://cdn.tailwindcss.com"></script>`
- 阿里巴巴普惠体 3（55-Regular / 65-Medium / 85-Bold 三档）通过 chinese-fonts-cdn.deno.dev 加载
- 字体声明：`font-family: "Alibaba PuHuiTi", "AlibabaPuHuiTi-3-55-Regular", "PingFang SC", "Microsoft YaHei", system-ui, sans-serif;`
- 无 `<script>` 交互逻辑（除 Tailwind CDN）
- **禁止跨 HTML 跳转**：6 份 HTML 之间不允许出现 `<a href="0X_xxx.html">` 形式的链接（顶部导航条、底部 footer、上下文"← 上一篇 / 下一篇 →"全部禁止）。页内 anchor（如 `<a href="#top-players">`）允许
- 所有 `<img>` 的 `src` 必须为 `data:image/...;base64,...`
- 内联 SVG 必须含 `viewBox` 属性；每张 SVG 必须承载真实数据（坐标轴 + 数据标签），**禁止纯装饰性 SVG**
- 不写 `<footer>` / "Continue Reading" / "六份 HTML 导航" 区块
- 不写 `video_*.html` / 类似博主拆解的产物
- 不写"完成进度 / 报告交付 / 已交付"等工程进度章节

### 数据缺口的诚实标注

当某个维度公开渠道深度不足时，禁止用"据相关数据""根据行业惯例""有从业者反映"等模糊话术补满。改写为：

- 在该章节末尾用判断卡片明示："本节关于 X 的数据，公开渠道仅有 Y 一份且时效性为 2023 年，建议读者结合 Z 维度自行判断"
- 在 `00_overview.html` 的"这份报告能帮你回答什么"小节列出**不能**回答的问题
