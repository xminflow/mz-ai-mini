# 课件制作规范（VIP 课程 `public/courses/`）

本文件约束本目录下课程课件的写作、视觉与技术约定。新增/修改课件（`.md`）前先读一遍，逐条遵守。你写的内容只能放在创作区（temp）目录下，其他目录的文件都不允许修改，只能用户自己修改，相当于你只提供底稿，我自己来负责合成为真正的课件

## 一、受众与写作目标

- 受众：已完成第一阶段、独立做过并上线过全栈应用的学员，有基础。
- 但写作要做到**「没接触过这些概念的人也能一次读懂」**：每遇到一个新概念，先用真实场景切入 + 大白话类比讲清「是什么、为什么需要」，再给术语，不留「默认你已懂」的跳跃。
- **不重复讲第一阶段已讲的基础**（终端 101、如何装 Node 等），引用到时一句话带过。
- 贯穿主线：用「学员第一阶段做的全栈应用」当练习仓库，逐节往里加真配置；每节开头接住上一节、结尾引出下一节。

## 二、每节结构（五段）

1. **痛点开场**：用学员真会遇到的场景切入，先共鸣。
2. **大白话 + 类比**讲清「是什么、为什么」，先讲清再给术语。
3. **手把手实操**：每条命令都给「该敲什么」+「敲完会看到什么」（预期输出或截图占位）。
4. **常见坑 + 排错**：新手最容易卡的点单独拎出来。
5. **总结**：回顾本节关键点收束 + 引出下一节。

> 小标题要自然，别把「痛点开场」这类段名当标题。**结尾一律用「## 总结」，不要写「本节产出」小节。**
> 篇幅：每节要厚，约 4000–6000 中文字（重头节靠上限）。

## 三、口吻与写作风格（硬规则）

- 尽量参考我的手写风格，比如AI时代下的程序员发展路线这篇内容
- **不用第一人称**：正文不出现「我 / 我们」指代作者或讲师，连引号内举例的读者口吻也避开（「帮我看看」→「帮忙看看」）。面向读者一律用「你」。
- **有立场、敢下结论**：用无人称权威句式表达取舍——「更推荐 X」「这门课建议…」「Y 已经过时、不在一个维度」。
- **禁研究报告腔**：不要导航句、不要交代研究过程、不要 `*未核实*`/`*置信度*` 标记、不要独立《数据来源》节、不要 emoji callout、不要几乎逐句加粗、不要每个条目套同一模板。
- **禁不自信 / 免责腔**：不要「以官网为准」「仅供参考」「拿不准就…」等。时效当确定事实陈述（如「截至 2026 年中」）。

## 四、命令框约定

- 代码块只给「该敲的部分」，**不带 `$` / `>` / `#` 提示符前缀**（新手会连前缀一起敲进去）。
- 命令与其预期输出**分开**：命令用 ```bash，输出用 ```text 或引用块。
- 多系统差异用中文标签行区分（如「macOS / Linux」「Windows（PowerShell）」）。
- SVG 示意图里的 `$ claude` 等是「终端命令」的视觉符号，可保留（那不是可复制的命令框）。

## 五、事实准确性

- 只写**核实过的高置信事实**。
- Claude Code：以 `code.claude.com/docs` 官方文档 + 本机实测双验；**剔除内部增强构建独有的特性**，只教公开通用能力。
- Codex：以 `developers.openai.com/codex` 官方文档核对（本机未装就不谎称实测）；随版本变动快的项（子命令名、弃用状态）写「以 `xxx --help` 为准」。
- 计费类**不写死单价 / 每日条数**，用「约 / 区间」，让学员以自己账号计费页为准。
- 不确定、文档也没写死的具体字段/命名，**绝不编造**，留 `<!-- TODO 核实: 具体问题 -->` HTML 注释交主编补，正文里不写含糊或免责话。

## 六、可视化

### 概念图 → 手写内联 SVG（已启用 rehype-raw）
- 风格：线 + 点 + 框 + 标签的克制风格。深色底 `#0d0d12`（或透明）、中性白字 `#e5e5ea`。
- 品牌色点睛：主蓝 `#0099ff` / 靛蓝 `#155eef`；暗金 `#eaaa08`（Codex / 警示）；翡翠绿 `#16b364`（成功 / 产出）；紫 `#8c5eff`；粉 `#d42672`；弱化灰 `#8a8a94`。
- `viewBox` + `width="100%" height="auto"`，字号 ≥ 12。实线 = 去程 / 主流程；虚线 = 返程 / 循环。**箭头方向务必核对**（历史出过「返回箭头画反」）。
- 每节 1–2 张，不堆砌。写完**务必用 chrome-devtools 截图自核**（箭头方向、文字不溢出、深色可读）。

### 横向对比 → Markdown 表格；真实界面 → 图片占位
- 多维对比（选型、权限模式等）用 Markdown 表格。
- 真实界面（命令输出、审批提示、IDE 截图）用标准 Markdown 图片，路径 `/courses/<章>/img/xxx.png`（作者后补 PNG），占位处写 `<!-- 截图: 描述该截什么 -->`。
- **不要用** Obsidian `![[...]]` 图片语法（阅读器不渲染）。

### 动画（可选，用于「讲活」概念图）
- SVG 概念图动画写在该 SVG 内联的 `<style>` 里，用 **CSS 滚动驱动动画**（`animation-timeline: view()`，滚入视野触发、播一次、不循环）。
- 必须 `@media (prefers-reduced-motion: reduce)` 关闭动画；用 `@supports (animation-timeline: view())` 包裹，不支持的浏览器优雅降级为静态终态图。
- 动画类名/keyframes 名加前缀避免跨图冲突（如 `kx-`）。

### 终端演示 → asciinema
- 在课件里用围栏块触发，块内容为 `.cast` 的 public 绝对路径：

  ```asciinema
  /courses/<章>/casts/<名字>.cast
  ```

- 由 `src/features/course/components/AsciinemaCast.tsx`（滚入即播一次、动态加载、尊重减少动态）渲染；播放器 bundle 在 `public/vendor/asciinema/`。
- cast 用 `website/scripts/gen-cast.mjs` 手写脚本化生成（比真机录制更干净、无手误、节奏可控），产物写入 `public/courses/<章>/casts/`。
- **画面/字幕禁英文品牌名**（只用「微域生光」）**与政治敏感词**（「翻墙」等，改用「国内直接可用 / 免代理可达」）。

## 七、阅读器渲染约束

- 渲染栈：`react-markdown` + `remark-gfm` + `remark-math`(KaTeX) + `rehype-prism-plus`(代码高亮) + `rehype-raw`(内联 HTML/SVG) + 自定义 ```asciinema 块。
- 可用：标题 / 列表 / 任务列表 / 表格 / 引用 / 围栏代码(带语言高亮) / 行内与块级公式 / 标准图片 / 内联 SVG·HTML / ```asciinema。
- 图片、cast 一律用 public 绝对路径 `/courses/<章>/...`。

## 八、落地结构与验证

- 每章一个目录 `public/courses/<章id>/`：`sections.json`（小节清单）+ 各节 `.md` + `img/` + `casts/`；在 `public/courses/manifest.json` 注册章节。
- 课程页登录后访问 `/course/<章id>/<节id>`；本地起服务用 `node node_modules/next/dist/bin/next dev`（绕过 pnpm 预检），登录用 `/login` 的「本地开发登录」（填 `dev_local`）。
- 大批量长课件**派 Agent 写**，给精确规格 + 已核实事实清单；写完 grep 复核「第一人称 / 本节产出 / TODO」归零，再起 dev server + dev-login，用 chrome-devtools 在真实页核对渲染、动画、asciinema。
