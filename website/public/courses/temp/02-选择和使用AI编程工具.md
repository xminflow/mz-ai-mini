# 选择和使用 AI 编程工具

当前阶段我们只聊Claude Code、Codex、Kimi、GLM 这四个AI编程工具和对应的模型，Claude code与Codex是目前最好的AI编程工具，当然这两个收费偏贵。以前我们可能为了能够更高效高质量地产出可靠的代码，即使贵一点也愿意去购买claude code或者codex，但是现在已经不一样了，国内自研的模型能力已经追上了一流梯队，我们完全可以选择更便宜，不需要处理网络问题的国产模型，kimi-3的出现基本上标志着国产模型也可具备最顶尖的能力，可以放心切换过来，当然我们的课程还是对准业界最高标准，使用claude code来完成讲解

## 分清楚AI编程工具和模型的关系
我们常说的claude code ，codex其实是一个编程工具，也就是业界常说的智能体，harness工程。这个编程工具底层需要有一个模型作为大脑来提供思考能力，否则就是一段没有任何智能的普通工具而已，claude code底层对应着Anthropic家的claude模型，比如代号为 claude sonnect 4.6 ，claude opus 4.8等，codex这个工具对应着Openai家的模型，比如gpt5.4 。国产的有kimi code，底层也有月之暗面自家的模型驱动，模随着模型能力的升级，模型代号也几乎每一两个月都在更新

现在我们了解了AI编程工具和模型其实是两个东西，从AI编程工具的角度而言，目前业界公认做得最好的是claude code，所以我们的课程也是以claude code为主来开展，但实际上大家都在进步，不同AI编程工具使用方法也差不太多，上手很简单，我们更重要的是学习技术和架构能力，工具并不是那么的重要，随时可以切换


## Claude Code：多形态共用一个引擎，管控做得最细

Claude Code 的性格，是把「怎么管住 AI」这件事做得最细。它的看点不在模型强不强——模型强弱一个月一变——而在于围绕权限、边界、回滚这些「兜底机制」铺得最密。如果你想系统地学一遍「怎么驾驭一个能自己动手的智能体」，它这套机制是最好的教材。

### Claude code的形态

**它有多少种形态。** 终端 CLI 是全功能形态；VS Code 和 Cursor 用同一个扩展；JetBrains 全家桶有插件，但要单独装 CLI；桌面 App 覆盖 macOS 和 Windows，Linux 版从 7 月开始 beta；网页版直接在 `claude.ai/code` 上跑，本地什么都不用装；手机 App 也能用；再往外，Slack 里能 `@Claude`，GitHub Actions 和 GitLab CI 里能让它自动审 PR、分流 issue。

关键在于官方那句话：这些形态共用同一个引擎，你写的 `CLAUDE.md`、你的设置、你配的 MCP 服务，在所有形态里通用。这意味着你在终端里调好的一套规矩，切到网页版、切到手机上继续用，规矩还在。这个设计对实际工作流的价值，比多一个 IDE 插件大得多。

装它就一条命令：

```bash
curl -fsSL https://claude.ai/install.sh | bash
```

Windows 的 PowerShell 里是这条：

```powershell
irm https://claude.ai/install.ps1 | iex
```

官方推荐这种原生安装方式，因为它会自动后台更新。用 Homebrew 或者 WinGet 装也行，但都不自动更新，得自己惦记着。

### 权限模式

它有六种权限模式，从最保守的只读，到边审边改，到探查模式，到全自动但有安全分类器兜底，到只放行预先批准的工具，最后到完全不问的模式——最后那个官方写得很直白，只能在隔离容器或虚拟机里用。在终端里按 `Shift+Tab` 就能在前三种之间循环切。另外它有个「受保护路径」的概念，`.git`、`.claude`、`.bashrc`、`.npmrc` 这些，除非开最激进的模式，否则任何模式下都不会自动放行写入。这个设计很关键，因为新手最容易被坑的就是 AI 悄悄改了 git 配置或者 shell 启动脚本，然后整个环境莫名其妙。

教不教得会规矩？这是它做得最细的一块。项目根目录放一个 `CLAUDE.md`，每次开会话自动加载，官方建议控制在 200 行以内——这个建议值得听，写太长它反而抓不住重点，跟给新人写入职文档是一个道理，写五十页没人看，写两页人人都记得住。除此之外还有一套 skills 机制，把一个反复要做的流程写成 `SKILL.md`，之后用斜杠命令调用，也可以让它自己判断该不该用。这里有个变化要注意：**「自定义斜杠命令」这个说法已经过时了**，官方把它并进了 skills，老的 `.claude/commands/` 目录还能用，但那只是向后兼容，新东西都往 skills 里写。

再往深走还有 hooks——在会话开始、工具调用前、工具调用后这些生命周期节点上挂自己的脚本。这个能力被严重低估了。举一个典型用法：挂一个工具调用前的钩子，凡是命令里出现生产环境的数据库地址，直接拦掉。这就是把「AI 是内奸」这个判断真正落到了机制上——不靠它自觉，靠你设的闸门。

Claude code 有 `/rewind` 做检查点回滚，能退到某次改动之前，甚至能退到 `/clear` 清空会话之前。

Pro 档每月 20 美元（年付合每月 17），Max 分 5 倍和 20 倍两档，分别是每月 100 和 200 美元。额度机制是 5 小时滚动窗口加上一个周窗口，官方从来不公布具体条数，也别去网上找那些「实测每天能用多少条」的帖子，因为它跟你用什么模型、开多长上下文、有没有派子代理直接相关，别人的数字没有参考价值。会话里敲 `/usage` 看自己的实际消耗，这才是唯一靠谱的办法。官方倒是给过一个企业侧的实测区间：平均每个开发者每个活跃日大约 13 美元，每月 150 到 250 美元，九成用户单日不超过 30 美元。这个数字可以帮你判断：如果是重度使用，订阅制比按量计费划算得多。

**关于 Claude Code 最需要记住的一条限制：官方明确不支持接第三方模型。**

网上有大量教程教你「把 `ANTHROPIC_BASE_URL` 一改就能用国产模型驱动 Claude Code」。这个操作在技术上确实能跑通，但官方文档写得很清楚：Anthropic 不背书、不维护、不审计任何第三方网关产品，也不支持通过任何网关把 Claude Code 路由到非 Claude 模型。模型配置页还专门补了一句——`ANTHROPIC_BASE_URL` 改的是请求发到哪里，不是改由谁来回答。

官方文档里真正支持的换端点用法只有两类：一类是云厂商托管的 Claude，比如 Amazon Bedrock、Google Cloud 的 Agent Platform、Microsoft Foundry，各有各的开关环境变量；另一类是企业自建的网关，但上游转发的仍然必须是 Claude 模型。

## Codex：把编程工具做成了通用工作台

OpenAI 这边的路子跟 Anthropic 明显不一样，而且这个差异这半年变得特别清楚。

最直观的信号：**Codex 的独立桌面 App 没了，7 月 9 号并进了 ChatGPT 桌面 App。** 文档站也一样，原来的 `developers.openai.com/codex` 现在整个跳到 `learn.chatgpt.com/docs`，Codex 的文档并进了 ChatGPT 的统一文档站。

这两件事合起来看，OpenAI 的意图很明白：他们不打算把 Codex 做成一个「程序员专用工具」，而是要把它做成 ChatGPT 这个通用助手的一只手——一只能真正动你电脑、动你代码库的手。

装它也是一条命令：

```bash
curl -fsSL https://chatgpt.com/codex/install.sh | sh
```

也可以走 npm：

```bash
npm install -g @openai/codex
```


### 权限体系
Codex 的权限体系跟 Claude Code 长得不一样，它是审批策略和沙箱模式两个维度交叉。审批策略三档：全部不信任要问、按需要问（默认）、从不问。沙箱模式也三档：只读、工作区可写（默认）、完全放开。官方推荐的日常组合是「工作区可写 + 按需要问」。

Codex 用 `AGENTS.md`，机制比 Claude Code 的更复杂一点：它是分层加载的，先读用户目录下的全局配置，再从 Git 仓库根目录一路往当前目录走，越靠近当前目录的文件优先级越高、会覆盖前面的。合并总量有上限，默认 32 KiB，超了就截断。这个分层设计在大型单仓多项目的场景下很好用——仓库根定通用规矩，各个子项目自己定各自的。

命令行这边它给了二十多个子命令，挑真正常用的说。`codex exec` 是非交互执行，专门给脚本和 CI 用的，带 `--json` 能输出 JSONL，带 `--output-schema` 能让它按你给的结构吐数据。这个能力后面讲发散场景的时候还会提到，它是把 AI 塞进自动化流水线的关键接口。`codex resume` 续上一次会话，`codex fork` 从中间某个点分叉出一条新线，`codex review` 做代码审查。GitHub 上还能直接在 PR 里 `@codex review`，或者 `@codex fix the P1 issue` 让它去修。

模型这边现在主推 GPT-5.6 系列，分三个档：Sol 是旗舰，官方定位复杂编程、计算机操作、研究和安全；Terra 是日常均衡档；Luna 是最便宜最快的。不必去记默认是哪个——官方自己文档里两处口径都不完全一致——直接 `/model` 切，用哪个心里有数就行。

价格上它的档位比 Anthropic 细：免费档、8 美元的 Go 档、20 美元的 Plus、100 美元起的 Pro、以及按人头算的 Business。多一个 8 美元的入门档，对预算紧的人是个真实的选项。另外它支持用 API key 计费，按 token 付费，官方定位是适合 CI 这类共享环境，但要注意这条路**不包含云端功能**，比如 GitHub 上的自动代码审查就用不了。

## Kimi：模型跳得最快，接入路径最容易配错

聊国产两家之前，先把一个旧印象丢掉：它们现在真正的竞争力不是「便宜的替代品」。这半年模型能力追得非常猛，加上国内网络直接可用，对国内学员来说，这已经是可以当主力用的东西，而不是退而求其次的备选。工具链稳定可达这一条的实际价值，往往比跑分高几个百分点大得多——链路稳，你才可能把它真正接进日常工作流。

月之暗面这半年的节奏可以用「疯」来形容。K2.5、K2.6、K2.7 Code，然后 7 月 17 号直接放出 K3：2.8 万亿总参数的混合专家架构，100 万 token 上下文，思考模式常开，用一个 `reasoning_effort` 参数在低、高、最高三档之间调。官方还预告 K3 的权重会在 7 月 27 号之前发布，说它是第一个达到这个参数规模的开源模型——不过截至目前，权重还没放出来，所以现在看到任何说「K3 已经开源」的说法，都属于抢跑。

在售的模型现在是三档：K3 主打长程编程和知识工作，K2.7 Code 是编程专用、256K 上下文，K2.6 是通用多模态。

**官方 CLI 刚刚换代，这是最容易踩的第一个坑。** 原来那个 Python 写的 `kimi-cli`，官方已经明说逐步停止维护了；现在主推的是 TypeScript 写的 **Kimi Code CLI**，仓库是 `MoonshotAI/kimi-code`。如果搜到的教程还在教你装 `kimi-cli`，那篇教程已经过时了。

新的装法是这条：

```bash
curl -fsSL https://code.kimi.com/kimi-code/install.sh | bash
```

Windows 上：

```powershell
irm https://code.kimi.com/kimi-code/install.ps1 | iex
```

Windows 用户注意，它需要先装好 Git for Windows，因为这个 CLI 用内置的 Git Bash 当 shell。

**第二个坑，也是最多人栽的地方：Kimi 提供了两条 Anthropic 兼容路径，而这两条路的鉴权变量不一样。**

一条是开放平台按量计费的路子，地址是 `https://api.moonshot.cn/anthropic`，鉴权必须用 `ANTHROPIC_AUTH_TOKEN`。另一条是 Kimi Code 订阅制的路子，地址是 `https://api.kimi.com/coding/`，鉴权用的是 `ANTHROPIC_API_KEY`，而且这个 key 要在 Kimi Code 的控制台里单独创建。

把两条路的变量名记混了，症状不是报一个清清楚楚的鉴权错误，而是各种莫名其妙的失败。官方文档还专门强调了一句很值钱的话：**变量必须配全，漏配会在对应场景里静默失效。** 比如只配了基础的两三个变量，主会话看着好好的，一旦派出子代理、或者触发上下文压缩，就会悄悄降级到一个没预期的行为上。

配全大概是这么一串（走开放平台按量那条路）：

```bash
ANTHROPIC_BASE_URL=https://api.moonshot.cn/anthropic
ANTHROPIC_AUTH_TOKEN=你的Kimi API Key
ANTHROPIC_MODEL=kimi-k3[1m]
CLAUDE_CODE_SUBAGENT_MODEL=kimi-k3[1m]
ENABLE_TOOL_SEARCH=false
CLAUDE_CODE_AUTO_COMPACT_WINDOW=1048576
CLAUDE_CODE_EFFORT_LEVEL=max
```

还有几个按模型别名映射的变量也要一并设成同一个模型。另外注意一个优先级问题：`~/.claude/settings.json` 里的配置优先级高于终端里 export 的环境变量，所以如果 export 了半天没生效，多半是那个文件里还留着旧值。配完敲 `/status` 核对一下 Base URL 和 Model，这是唯一可靠的验证方式——别凭「它回话了」就认为配对了。

订阅套餐这边，Kimi Code 的权益跟 Kimi 会员绑定，档位叫 Andante、Moderato、Allegretto，从低到高。额度机制是 7 天周期刷新且不累积，另外叠加一个 5 小时滚动限流，超额可以买加油包。价格大致在每月几十元到两百元这个量级。

最后说一句评测。网上流传的那些 K3 对比跑分数字，这里一个都没列，因为查下来全部出自第三方博客和聚合站，官方域名上找不到。官方自己给的口径只有相对上一代的提升幅度。核不实的数字，不写。

## GLM：官方接入最规范，但额度机制有个必须知道的倍率

智谱这边的节奏也不慢：GLM-5 在 2 月，GLM-5.1，然后 6 月 16 号 GLM-5.2。744B 总参数、约 40B 激活的混合专家，100 万 token 上下文，最大输出 128K。**现在网上还在写「GLM-4.6 是主力」的资料全部过期了**，GLM-4.7 现在只是套餐里的一个低档位模型。

智谱最突出的一点，是它对接入 Claude Code 这件事的态度最正面、文档最规范。base_url 是 `https://open.bigmodel.cn/api/anthropic`，官方文档直接给 Python 的 `anthropic` SDK 示例，Claude Code 侧则教你写进 `~/.claude/settings.json` 的 env 段，配 `ANTHROPIC_BASE_URL`、`ANTHROPIC_AUTH_TOKEN` 和 `API_TIMEOUT_MS`，还给了模型映射变量。它甚至提供了一个配置助手，一条命令帮你把 Claude Code 的安装、Key 配置、MCP 管理和套餐加载全办了：

```bash
npx @z_ai/coding-helper
```

这里有个细节容易搞错：**不同工具用的 base_url 不一样。** Claude Code 走 `/api/anthropic` 这个路径，其他工具走的是 `/api/coding/paas/v4` 系列的路径。照着别人给的地址往 Claude Code 里填，很可能填错。

**现在说它的额度机制，这一段是这一节里最实用的信息之一，很多人订阅了之后体验落差大就栽在这。**

Coding Plan 分 Lite、Pro、Max 三档，三档都能用 GLM-5.2。额度是 5 小时滚动加周上限双重限制。官方给的量级大概是：Lite 每 5 小时约 80 次提示、每周约 400 次；Pro 是 400 和 2000；Max 是 1600 和 8000。

但**关键在这句官方注解：一次提示通常会触发 15 到 20 次模型调用。** 也就是说敲一次回车，消耗的不是「一次」，而是一整轮 agent 循环里的十几次调用。理解这一点，对「80 次提示」这个数字的感受就完全不同了——那不是 80 句话，那是 80 轮完整任务。

还有一个更容易被忽略的：**高峰时段有消耗倍率。** 每天下午 14 点到 18 点这个区间，高阶模型按 3 倍消耗计，非高峰时段 2 倍（9 月之前非高峰有 1 倍的临时活动）。这意味着同样的活，放在下午干和放在晚上干，额度消耗差好几倍。不少人抱怨「这套餐怎么下午就用完了」，根因就在这。


另外有个使用范围的限制要注意：Coding Plan 的额度只能在官方支持的工具和环境里用，不能当通用 API 随便调。官方支持清单里有 Claude Code、Kilo Code、OpenClaw、OpenCode、TRAE、CodeBuddy 等。

套餐里还自带一套 MCP 工具集：视觉理解、联网搜索、网页阅读、开源仓库访问，Lite 档四项合计每月约 100 次，Pro 约 1000 次，Max 约 4000 次。这个附赠品比看上去有用，尤其是联网搜索和网页阅读——让它去读一份最新的官方文档再动手，比让它凭记忆写靠谱得多。

开源这边，GLM-5 系列的权重放在 `zai-org/GLM-5`，BF16 和 FP8 都有，Hugging Face 和 ModelScope 上都能拿。


评测方面智谱给得很敢：官方公布 Artificial Analysis 综合分 51、称并列全球第三；FrontierSWE 仅比 Claude Opus 4.8 低 1%；Terminal-Bench 2.1 拿 81.0，Opus 是 85.0；SWE-Bench Pro 62.1。**这是过去半年国产厂商在官方口径上最激进的一次正面对标——敢跟对方最强的模型逐项摆数字，而且只差个位数百分点，这件事本身就说明差距被压得有多小。** 当然要清楚：跑分能告诉你它大概在什么段位，告诉不了你它在你那个具体项目上好不好用。段位差不多的模型，真正的差距在你的项目规矩教得够不够清楚。

## 别把它只当编程工具用

前面全在讲编程。但如果只把这些工具用在写代码上，大概只用到了它三分之一的价值。这不是主观感受，是有官方数据的。

Anthropic 在 6 月发过一份官方研究，统计了 Claude Code 的会话到底在干什么。结果是：写代码约 25%，修代码约 26%，测试和编排代码约 5%——这三项加起来才刚过一半。剩下的将近一半里，**操作软件占 17%，规划或探索占 14%，产出分析或散文占 13%**。而且趋势更能说明问题：从 2025 年 10 月到 2026 年 4 月这半年，写作和数据分析类的会话占比大约翻了一倍，从 10% 涨到 20%；而「修坏掉的代码」这一项，从 33% 掉到了 19%。

翻译成大白话：**这个工具正在从「帮你写代码」变成「帮你干活」，而且用户已经先一步走到那儿了。**

Anthropic 官方博客里还给了几个非工程团队的真实用法，比任何教程都有启发：

产品设计团队把 Figma 设计文件直接喂给它，让它自主开发功能；更妙的是他们用它在设计阶段就梳理错误状态、逻辑流转和系统状态，把边界情况提前挖出来——这活以前是等到开发甚至测试阶段才发现的。

增长营销团队拿它处理几百行的广告投放 CSV，让它找出表现差的那些，然后生成新的变体；还让它写了个插件批量产出上百个广告素材变体。

法务团队用它做了个「电话树」原型，帮团队成员快速找到该找哪个律师。

还有个数据科学家，压根不熟 TypeScript，靠它建了一个完整的 React 应用来可视化模型性能。

看出规律了吗？**这些人的共同点是：他们有一个明确的、自己能验收的目标，但缺少把它实现出来的手艺。** 而这正是这类工具最能发挥价值的地方。

OpenAI 那边的方向更直白。他们给 ChatGPT 设了一个「Work 模式」，官方定义是：想要一个答案、一段解释、一次头脑风暴或者一份短草稿，用 Chat 模式；想让它**完成一件有明确产出的任务**——一份简报、一套幻灯片、一份分析、一个周期性更新、一条工作流、一个你能拿去用的文件——用 Work 模式。官方的用例页面上列的全是非编程场景：管收件箱、生成每日工作简报、把反馈转成行动项、生成幻灯片、准备会前简报、把会议记录转成待办、把研究转成决策备忘录、准备业务评审材料、写每周工作总结。

**几个明天就能试的场景。**

第一个，把日志喂给它。服务半夜挂了，早上起来面对几万行日志。别自己一行行翻：

```bash
tail -200 app.log | claude -p "找出里面的异常，按严重程度排序，每条说清楚是什么触发的"
```

这是官方文档里给的用法。同样的思路可以套到任何命令输出上——`git log`、`docker logs`、`kubectl` 的输出，管道给它，让它读。

第二个，把它塞进流水线。`codex exec` 这个子命令就是干这个的，它非交互、能吐 JSONL、能按你给的结构输出。所以可以在 CI 里让它做完一件事，把结果 `jq` 出来喂给下一步。发布说明、变更日志、依赖升级报告，这类每次发版都要写一遍的东西，全可以自动化掉。

第三个，批量文件处理。这个场景被严重低估了。一个装满 PDF 的目录要提取信息、几百个文件要按规则重命名、一堆 Markdown 要统一格式——这些活写脚本要半天，交给它连脚本带执行十分钟。关键是它不只是生成脚本，它能自己跑、自己看结果、自己改。

第四个，当调研助手用。要选一个技术方案，让它去读几份官方文档再给结论，比让它凭记忆答靠谱得多。这也是为什么前面说 GLM 套餐自带的联网搜索和网页阅读那几个 MCP 工具比看上去有用。

第五个：**当一个不会累的审查者。** 写完一段东西——代码、方案、文档都行——让它站在反对者的立场挑毛病。它挑出来的十条里可能有七条是废话，但剩下三条经常是你自己盯着看八遍也看不见的。这个用法完美契合上一节的结论：它不担责，所以它的意见你只能当参考；但正因为它不担责，它挑起毛病来毫无心理负担，不用顾及你的面子。这一点，人类同事反而做不到。

## 那到底从哪个开始

四个都是第一梯队，没有错误选项。别纠结「哪个最强」，按自己的处境挑一个开始就行。

**在国内、网络条件受限，或者预算敏感，直接上国产两家，这不是将就。** 这半年它们的进步是实打实的，智谱敢在官方口径上跟 Opus 4.8 逐项比数字、只差个位数百分点，这在一年前不可想象；月之暗面半年连跳三代、把上下文做到百万级。两家里，从**智谱**入手更省心，理由是它对接入 Claude Code 这件事的文档最规范、路径最清楚，还提供配置助手，踩坑概率最低。**Kimi** 模型迭代更凶、上下文更长，但它那两条接入路径的鉴权差异确实容易配错，等把配置这套东西摸熟了再上它，体验会更顺。

**本来就是 ChatGPT 的重度用户，日常还有大量文档、材料、分析、汇报要产出，Codex 的整合度最高。** OpenAI 把它并进 ChatGPT 这个动作，方向很清楚——他们在做的是一个能动手的通用助手，而不只是编程工具。8 美元的入门档也让试错成本很低。

**想系统学一遍「怎么管住一个能自己动手的智能体」，Claude Code 这套机制是最好的教材。** 六种权限模式、受保护路径、hooks、检查点回滚，这套东西学会了，是能迁移到任何工具上的通用认知——包括迁移到国产工具上，因为国产两家的接入本来就是兼容 Claude Code 那一套。前提是网络条件允许。

**多试之后一定要挑一个沉下去。** 前面几个都试试没问题，手感对比出来了，就选定一个用够三个月，把项目规矩写好、把权限调到你敢放手的程度、把额度花在哪搞清楚。这三件事做扎实了，再换到任何一个新工具上，一天就能上手。反过来，如果一直停在「都试过、都不深」，换一百个工具，每一个都只用到皮毛。

工具是会一直换的，这半年就换了好几轮。但「怎么管住一个不担责的执行者」这套心法，不会换。

## 总结

这一节讲了四个工具，但真正要记住的是四个判断标准：**能不能管住它、能不能教会它规矩、出事能不能查能不能退、用不用得起以及额度花在哪。** 用这四条去衡量，面对半年后出现的任何新工具都不会慌。

四个工具是四种性格，都在第一梯队，各擅胜场：Claude Code 多形态一个引擎、管控做得最细，但官方明确不支持接第三方模型，那条路是社区路径、风险自担；Codex 正在从编程工具变成通用工作台，非编程场景是它的主推方向；Kimi 模型跳得最快、上下文最长，官方 CLI 刚换代，两条接入路径的鉴权变量不同是最大的坑；GLM 官方接入文档最规范、最适合新手，但额度有高峰时段倍率，不知道这一条会严重影响体验。**尤其要更新的一个认知是：国产模型这半年真的追上来了，对国内学员来说已经可以当主力，而不是备胎。**

还有一件事值得真的去试：**别把它们只当编程工具。** 官方数据摆在那，将近一半的会话根本不是在写代码。日志分析、批量文件处理、调研、材料产出、当一个不会累的审查者——这些场景的价值一点不比写代码低，而且门槛更低、见效更快。

工具选完、装好、规矩写好，接下来就是真正的功夫了：怎么把项目的规矩讲清楚，让它第一次就干对。下一节讲这个。
